Schema
JSON projections
Use -> for JSON and ->> for text. Missing paths return null. Text extraction also turns JSON null into SQL NULL. JSON keys are not inferred from the database schema.
The SDK's selectJson, jsonText and jsonValue helpers retain nullable result types.


Browse rows
Choose a table above and a test identity below. Reads and inserts use that identity's row-level security.





  


Export the current view to CSV
Exports the selected columns with the current filter, sorting and relationship scope under the selected identity. Reads start at the first page and remain live while exporting; data changes can affect later pages.
Spreadsheet mode protects formula-like text and uses blank cells for NULL. JSON-cell mode preserves types and NULL/empty-string distinctions; choose JSON cells when importing that file.
 


 




Saved relationship views
Stored in data-api.views.json. Definitions include your filter values. Review the file before sharing it. Row keys, row results, subjects and credentials are excluded. Support views include the configured identity name. Reopening starts at the first table; choose a visible row to continue the saved path.
  


Guided RLS checks
Generate checks from a saved view. Supply synthetic fixture keys and exact visible-row counts for each identity and step, then set status to reviewed. Each step needs a positive expectation. Checks use GET requests and never populate fixtures.
   
 
Saved in data-api.access.json. Run in CI with gregale data-api verify --access-checks data-api.access.json --fixture fixture.sql.


Import CSV into the selected table
Map headers to writable columns. Blank cells can remain values, use database defaults, or become NULL. Numbers use decimal notation; booleans use true/false; complex values use JSON. Imports run as the selected identity and database RLS still applies.
 
 
 
Batches contain at most 25 rows and commit independently. A refused batch inserts none of its rows. Uncertain rows are excluded from retry; read the table before deciding whether to import them manually.


Update or delete selected rows
Select rows using the checkboxes beside their actions. Selection is limited to the current page and requires a readable primary key and declared integer version. Each row commits independently under the selected identity and RLS.
Matching previews read live ordered pages under the selected identity, including filters and relationship scope. Up to 1,000 matching rows must fit completely within the chosen limit. Only the reviewed keys and versions are used after approval; this is not a database snapshot.
Read-only preflight verifies the pinned schema, current visibility, reviewed versions, and known writable fields. Successful checks allow approval for 60 seconds. Failed checks require a fresh preview. Write policies, constraints, and triggers remain enforced during execution; data can change after a check.
Rows to reconcile and retry
Reports contain run metadata and row indexes, excluding keys, row values, filters, and credentials. Use the reviewed preview to identify row indexes. Download the report before closing this tab. A retry report links its row indexes to the previous run; retries still require a new approval.
Reconcile conflicting and uncertain rows
Reads use the original identity and schema. Current matching values are only evidence of a potentially applied change. Hidden or absent rows do not prove deletion. Original outcomes and reports remain unchanged. New writes require fresh versions, readiness checks and explicit approval.
Changed, deleted, or unavailable rows are conflicts and require a fresh read. Uncertain operations may have committed; inspect the data before deciding what to do. Confirmed, conflicting, and uncertain rows are excluded from retries.


Bulk-operation history
Redacted reports are stored in data-api.bulk-history.json. Keys and reviewed values stay in this tab only, bounded to 20 snapshots and 10 MiB. Reopened snapshots require the original identity and schema, and new reads, previews, readiness checks and approval.
