# ADR-288 · Actions-owned release-tag deployments

- **Status:** accepted
- **Date:** 2026-09-27
- **Decision:** The workflow generated by `gregale github setup` listens for pushes to the configured production branch and `v*` tags. For tag pushes, the deploy Action proceeds only for a newly created, unforced SemVer release tag with a zero `before` SHA; deleted, moved, and invalid tags are successful skips. It submits the event's immutable `GITHUB_SHA` to Gregale rather than resolving the tag name again.
- **Why:** Selecting Actions as the production branch-push owner disables the GitHub App push path. The generated workflow previously listened only to the production branch, so SemVer tag releases were silently left without a deployment trigger.
- **Consequences:** Branch and release-tag pushes use the same Action authentication, wait behavior, rollout mode, and per-app concurrency. The event SHA pins source even if the tag moves after the workflow starts. Manual dispatch and custom refs remain deliberate deploy choices and do not use the push-event freshness checks.
- **Rejected alternatives:** Leaving tags to the GitHub App would split production deployment ownership and ignore the Action's selected rollout behavior. Fetching the mutable tag name after validation leaves a race in which the tag can move before source download. Triggering every `v*` tag without validating creation metadata would permit non-release and moved tags to deploy.
