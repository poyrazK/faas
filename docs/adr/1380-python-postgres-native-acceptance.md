# ADR-1380: Python PostgreSQL native acceptance

- **Date:** 2026-10-15
- **Status:** accepted; native execution pending
- **Context:** The PostgreSQL guest gate covers the SQL probe and shipped Node starter. Portable Python lifecycle and SQL tests do not establish that the shipped Python starter survives real Firecracker restore, credential rotation or scheduler recovery. Node-only guest evidence must not qualify both supported starter languages.
- **Decision:** Run the unchanged embedded `rest-api-postgres-python` source after the Node starter in the same disposable SQL journey. Package only the fixture's public CA under the existing `runtime/` COPY and select it with `SSL_CERT_FILE=/app/runtime/fixture-ca.pem`. The pinned libpq driver retains explicit system trust and `verify-full`; managed connection URIs and application code are unchanged. A portable regression materializes that exact source and requires the packaged CA to work and unrelated/malformed CAs to fail against TLS/SCRAM SQL.
- **Acceptance:** Add six Python phases: release and initial restore, ordinary-task migration-secret exclusion, retained-pool disconnect recovery, failed-hook cold fallback, running rotation/retirement, and parked rotation with scheduler recovery. Preserve the Node notes dataset across the Python deployment and require independent SQL content/count checks after each starter. Successful starter reads also require public writer-binding adoption receipts for the current deployment, credential generation, secret version and process generation from every inventoried resident. The ordinary API, scheduler and binding worker continue to own rotation and retirement.
- **Evidence compatibility:** Upgrade the guest contract, report and runtime manifest to version 3 with nineteen ordered phases. Require distinct probe, Node and Python source-archive and deployed app-layer hashes, plus unchanged shared executable/guest/kernel/builder/minimal-base artifacts. Version-1/version-2, partial Node-only and reused workload evidence cannot supply combined readiness and must be regenerated. Provider qualification remains version 8. Preserve bounded fragmented cleanup-log parsing, clean-source/native-host/expiry requirements, independent bundle approval and private no-overwrite publication. Allow 45 minutes for the expanded native journey.
- **Limits:** Portable SQL/TLS checks, verdict regressions and tagged compilation do not establish native guest or host leak acceptance. Execute the strict runner on a designated supported KVM host before qualification. This change enables no provisioning, rollout policy or provider resources.
