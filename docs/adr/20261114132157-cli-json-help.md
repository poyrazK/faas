# ADR-20261114132157: Structured discovery through the existing help command

Status: Accepted
Date: 2026-11-14
Related: ADR-083 (CLI discovery), ADR-20261023115741 (capability visibility),
ADR-20261026145832 (canonical command tree)

## Decision

`gregale --json help [COMMAND...]` returns version-1 structured discovery from
the same filtered manifest used by the command tree, completion and reference.
Root help lists every visible canonical command. A topic reports its canonical
and requested paths, known compatibility paths, immediate children, positional
markers, local flags, examples, notes and documentation URL. Flags expose their
spellings, value requirement, required/repeatable markers and closed choices.
Empty collections are arrays. Clients may ignore additional fields within the
version; incompatible interpretation changes require a new schema version.

The existing command-tree rewriter resolves older names. Unknown paths and
options fail with exit 1 and one existing Problem JSON diagnostic on stderr,
without a successful stdout result. No command parser or command handler is
executed to discover metadata. The manifest does not infer types, defaults,
output schemas or cross-flag validation from human descriptions.

Use the offline capability view: the selected connection's cached account
visibility when available, otherwise the catalog's GA/beta tier defaults.
Discovery does not contact the API, refresh the cache, require login, validate
saved connection settings or emit HTTP debug records. Existing dark-launch
and internal-hosting opt-ins still apply. The cache may be stale; this is not
an authorization decision.

Customer roots are the default. Root `--operator` adds operator and earlier
compatibility roots. Explicit topics remain inspectable under the same audience
policy as human help. `--all` is accepted; JSON always includes the complete
visible local metadata. Global options keep their existing prefix behavior.

Human `help` and command-local `--help` retain their current text contract,
including callers that set JSON mode globally. This provides structured
discovery through the explicit help command without changing existing help
renderers, successful operation output, error codes or execution semantics.

## Verification

Public-dispatcher tests decode complete documents, compare root and leaf
metadata with the manifest, resolve canonical and older names, check cached
capability filtering and environment-selected JSON, and verify offline use,
credential-safe diagnostics, empty stdout on failures and invocation isolation.
A built-CLI journey follows root discovery into invocation metadata and checks
alias resolution and invalid requests against an API that must receive zero
requests. Existing help, command-tree and generated-reference gates remain in
force.
