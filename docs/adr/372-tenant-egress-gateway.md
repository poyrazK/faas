# ADR-372 · Tenant egress leaves through a dedicated WireGuard gateway

- **Status:** accepted
- **Date:** 2026-09-29
- **Amends:** ADR-055 (per-host egress NAT). ADR-361's per-VM policy is unchanged and still runs on the compute node.
- **Context:** Tenant traffic has always been masqueraded out of each compute node's own interface. The address that shows up in an abuse report is therefore the node's own address, which also carries the control plane, deploys, the operator's SSH and the provider's own trust signals. The 2026-09-24 suspension ([ADR-361](361-tenant-egress-default-deny.md)) took the whole project down because tenant traffic and platform traffic shared one identity. ADR-361 made tenant egress narrow and observable. It did not give it a separate identity that can be rate limited, re-addressed, moved to a provider with an abuse desk, or cut off without touching the platform.
- **Decision:**
  1. **Opt-in per fleet.** The manifest declares `egress.tenant_gateway` with the gateway's WireGuard `endpoint` (`host:port`), `public_key`, a private IPv4 `tunnel_cidr` (/16–/29, not overlapping the tenant bridge or the overlay), and an optional `ssh_host`. Without it, egress is unchanged.
  2. **The operator provisions the gateway host.** Gregale converges it but does not create it: any Linux VM with a public address, ideally at a provider whose terms fit a multi-tenant egress IP. `gregalectl manifest ansible` puts it in the `tenant_egress_gateway` inventory group, and `make bootstrap-tenant-egress-gateway` converges it and then every compute node.
  3. **Compute nodes route only bridged tenant traffic into the tunnel.** Each compute node brings up `wg-tenant` with `Table = off` and policy routing that matches `iif br-tenants` from the tenant CIDR. Static-egress-IP VMs (ADR-119) sit outside that CIDR and keep their own SNAT out of the node's interface. Tenant traffic to the tenant bridge and the overlay stays on the main table. Everything else from the bridge uses a table whose default route is the tunnel. Host-originated traffic, including the bridge resolver's upstream queries, gatewayd and vmmd, never consults that table. A node's tunnel address is derived from its name (`<prefix>-N` → host N+1; the gateway holds host 1), so joined nodes get stable addresses without a registry.
  4. **Host policy follows the tunnel.** `HostPolicy.TenantEgressIface` (vmmd `FAAS_TENANT_EGRESS_IFACE`, Ansible `tenant_egress_iface`) makes the host forward chain accept bridged tenant IPv4 only out of `wg-tenant`, clamp the SYN's MSS to the tunnel MTU, and masquerade the tenant CIDR out of the tunnel. Tenant IPv6 egress stops: the tunnel is IPv4 only, and IPv6 out of the node's interface would bypass the gateway. The Go renderer and the Jinja template stay byte-identical (`make egress-check`).
  5. **Keys never leave the host that minted them.** Each compute node mints its own key and registers only its public key as a peer file on the gateway (`/etc/faas/tenant-egress/peers/<node>.conf`). `faas-tenant-egress-sync` assembles the config and applies it with `wg syncconf`, so live tunnels are not reset. The gateway mints its own key; the converge refuses to continue unless it matches the manifest's `public_key`, and prints the actual key. A full converge removes peer files for nodes no longer in the inventory.
  6. **The gateway is a second, independent deny layer.** In its own `inet faas_tenant_gw` table, the gateway drops tunnel traffic to private, loopback, link-local, CGNAT, benchmark and multicast ranges and to SMTP ports. It also drops non-TCP/UDP/ICMP protocols, peer-to-peer traffic between compute nodes, new inbound flows into the tunnel, and tunnel traffic addressed to the gateway itself (except ping). It clamps the server's SYN-ACK MSS into the tunnel, forwards tunnel traffic only out of its public interface, and masquerades it. The operator's own firewall on the host is left alone.
  7. **Failure is closed, not open.** If the gateway is down, tenant egress fails; it does not fall back to the node's own address. Inbound requests, wakes, the bridge resolver and the platform keep working. Falling back would put the node's address back into abuse reports at exactly the moment the operator is dealing with the gateway.
- **Consequences:**
  - Abuse reports name the gateway's address. The operator can re-address it, move it, or null-route it without touching compute nodes or the control plane. The flow log (ADR-371) still records the tenant's own source, so attribution is unchanged.
  - One more host to run. It is a single point of failure for tenant egress only. It needs no state beyond its key, so a replacement is one converge plus a manifest key change.
  - Tenant traffic pays one tunnel hop and 80 bytes of MTU. MSS clamping at both ends keeps TCP from relying on path MTU discovery.
  - Guest DNS answers still come from the node's address, because the bridge resolver is host-originated. It sends queries only, never tenant payloads.
  - A node joined with `node_join` registers its own peer while it converges, as long as the gateway is in the inventory. Otherwise the converge prints the key and address for a hand-managed gateway.
- **Alternatives rejected:**
  - *A dedicated egress NIC or IP per node:* the addresses stay tied to the compute provider and multiply with the fleet.
  - *A cloud NAT product:* ties the platform to one provider, and the provider's abuse handling is the problem being solved.
  - *An HTTP CONNECT proxy:* only covers HTTP-aware clients. ADR-361 allows plain TCP on declared ports.
  - *Falling back to direct egress when the tunnel is down:* rejected for the reason in decision 7.
