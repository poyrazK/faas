# ADR-20261031120000: PR previews of new services, skipped heads and production protocols

- **Status:** accepted
- **Date:** 2026-10-31
- **Amends:** ADR-095 (PR preview environments), ADR-20261030070000 (bot and draft policy), ADR-20261031090000 (route contract on previews)
- **Decision:** A sixth code review of PR previews found these gaps; this ADR fixes them.
  1. **A service the PR adds keeps the bound app's access gates, not its route contract.** Its preview takes the access and egress gates of the app the PR previews, because it has no production app of its own. ADR-20261031090000 made that copy include the route contract, which lists the bound app's routes: the new service then answered 404 `undeclared_route` for its own routes, or 503 `declared_route_policy_unavailable` when the contract came from an imported OpenAPI document. The new service now takes no route contract. Its access and egress gates also follow the bound app: `sync_preview_access_gates` updates the new services of the bound app's PR environments (members of a set whose root previews it, without a production app of their own), not their visibility. A backfill applies both to existing previews.
  2. **A service the PR adds belongs to its project's org.** Its row had no org, so the reservation gave it the PR author's personal org, and in an org-owned project `bind_project_workload_owner` refused the whole PR environment. It now takes the bound app's org.
  3. **A skipped head retires the PR's live preview.** With draft previews off, a PR turned back into a draft (`converted_to_draft`, now decoded), and a bot PR after bot previews are turned off, had their later events skipped while the preview served the last previewed head to the end of its lease. A skipped head now retires the PR's open previews, and the neutral `gregale-preview` check says so. With draft previews on, `converted_to_draft` changes nothing. The skip decision uses the PR's draft state as GitHub reports it now, after the current-head check, so a delayed event sent while the PR was a draft cannot skip or retire the preview of a PR that is ready for review.
  4. **A preview serves the protocols production serves.** Webhook previews were created without the production app's `websocket_enabled`, `streaming_enabled`, CPU and route-metrics settings (API previews copied them): a WebSocket app's preview answered upgrades with 501 `websocket_not_on_plan`, and streamed responses were buffered. Previews now copy them when created, and every new head refreshes the WebSocket and streaming switches. A service the PR adds keeps the defaults production would give it.
  5. **Previews cannot have custom domains.** `POST /v1/domains` for a preview app returns 409: a preview is torn down with its pull request or lease, and the domain stopped serving then while keeping its slot until the purge.
- **Why:** Previews of new services were broken or refused, policy-skipped PRs kept serving stale code behind a "skipped" check, and previews differed from production in ways that broke real-time apps.
- **Consequences:**
  - One migration replaces `sync_preview_access_gates()` (the trigger and its column list are unchanged) and backfills new-service previews in batches. An older githubd still copies the route contract onto new services it creates until it is upgraded; the next head from the new release clears it.
  - `pull_request` deliveries with action `converted_to_draft` are now processed. Every non-closed event checks the PR's current state with GitHub before the skip decision, one request per event, as previewed events already did.
  - Existing previews take production's WebSocket and streaming switches on their next head; CPU, like RAM, is set when the preview is created.
- **Rejected alternatives:**
  - **Give a new service the bound app's route contract with its own OpenAPI document.** A new service has no imported document, and importing the PR head's document lets PR code define its own gate.
  - **Keep a converted draft's preview serving.** A project that turned draft previews off asked for drafts not to be previewed; the old head under the PR's preview link misleads reviewers.
  - **Retire bot and draft previews when the policy is changed.** apid does not know which open previews belong to bot or draft PRs; the PR's next event does, and GitHub sends one for every push.
