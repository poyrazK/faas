# ADR-277: Pinned service-binding handler smoke test

- **Status:** accepted
- **Context:** `gregale bindings verify` proves that a caller guest can resolve a private service alias, validate the workload CA, pass binding and target authorization, and find a healthy endpoint. It deliberately does not wake a parked target or invoke customer code. Operators who need to validate a target handler before routing traffic currently have to construct the internal request themselves.
- **Decision:** Add `gregale bindings smoke <caller> <service> --deployment <id> --path <path>`. Gregale admits a bounded platform-owned task in the caller's deployment, verifies that the service is declared, and sends exactly one GET over `https://<service>.internal` with normal TLS certificate verification and `Gregale-Target-Deployment` set to the required live deployment UUID. The proxy validates that the deployment belongs to the authorized target service, wakes that exact deployment if parked, and strips the override header before forwarding. The command accepts any 2xx status by default or can require an exact status with `--expect-status`.
- **Consequences:** The operation is intentionally separate from the side-effect-light `bindings verify` preflight. It invokes customer code and can wake the selected deployment, so callers must provide both an exact deployment and a path. The request has no body or caller-supplied headers, does not follow redirects, never disables TLS verification, and does not retain the response body or request query in the report. The origin-form path is bounded and cannot select another host.
