# ADR-1647: Complete managed graph retirement with binding enforcement

- **Status:** accepted
- **Date:** 2026-10-17
- **Related:** ADR-1331, ADR-1646
- **Problem:** Binding policy enforcement rejects the ordinary release publisher used by complete GitOps workload retirement. Candidate qualification authorizes replacement recipients, but cannot authorize an empty graph. Disabling policies to clean up would discard the intended protection.
- **Decision:** Add private checked authority exclusively for complete removal. Reserve retirement through the existing reviewed `workload_pruning_policy: retain` protocol. Freeze each retirement's binding policy mode and monotonic revision at reservation. At cutover, require the current source approval, generation, intent version, reviewed plan, controller lease, original inventory and unchanged policy snapshots. Historical reservations without a snapshot cannot acquire enforced removal authority; review a fresh generation.
- **Scope:** The resulting project release must have zero members. Every non-preview project workload must be retiring in this reviewed source or already retired by it. A surviving caller or recipient blocks this path and needs a separately qualified replacement graph. No health probe against a removed deployment is required, and removal authority cannot grant traffic, activate candidates, reopen admission or authorize recovery.
- **Atomicity and audit:** Reuse the original project/app locks and the existing retirement cutover to withdraw routes and pause consumers/schedules with release publication. PostgreSQL records an immutable receipt containing the exact retirement IDs, policy snapshots, reviewed plan, source/revision/generation/intent identity, previous release and lease deadline. Deferred validation rechecks complete empty membership and current authority at commit. Memory publication uses a private grant under its single mutex and rolls back failed cutovers.
- **Completion:** Publication starts retirement; it does not certify completion. Preserve ADR-1331's gateway withdrawal generation, current-roster acknowledgements and scheduler-owned execution drain. Keep app identities, artifacts, queue bindings, accepted backlog and historical evidence. Source lease expiry after cutover cannot reopen the durable admission fence. Recovery still requires fresh reviewed preparation and qualification.
- **Migrations:** Append a new migration. Snapshot and audit history are immutable; downgrade refuses to discard enforced reservation or checked retirement history. Existing applied migration bytes and the original binding release guards remain unchanged.
- **Validation:** Portable memory/PostgreSQL lifecycle tests cover image/source cohorts, policy preservation, stale plans/policies/leases/approvals, surviving workloads, withdrawal convergence and retained backlog. PostgreSQL tests cover immutable history and migration round-trip. These fixtures do not establish native VM retirement or leak qualification; dedicated x86_64 Linux KVM acceptance remains required.
