# ADR-289 · Actions-owned mapped environment deployments

- **Status:** accepted
- **Date:** 2026-09-27
- **Decision:** `gregale github setup --deploy-branches branch=environment,...` generates push filters and environment routing for every mapped branch. Without that flag, setup reuses mappings already saved on the project. The workflow passes non-default mappings to the deploy Action as registered Gregale project environments and selects the matching GitHub Actions environment for protection rules. A `default` mapping omits the Action environment and uses the workflow's `production` GitHub Actions environment fallback. Manual dispatch runs only for the configured production and mapped branches; SemVer tag pushes continue to target the default deployment environment. Workflow concurrency groups are keyed by app and target deployment scope.
- **Why:** After Actions takes ownership of production pushes, githubd ignores App push deliveries. The setup command persisted branch-to-scope mappings, but generated Actions workflows only listened to the production branch, leaving mapped staging and test branches with no deployment path.
- **Consequences:** Actions and webhook mode now support the same configured branch set. The account-scoped GitHub status response includes saved project branch mappings so setup can reuse them. Non-default mappings require the corresponding Gregale project environment to exist, and repository owners can protect its matching GitHub Actions environment. A `default` mapping deploys to the default app scope while retaining the `production` GitHub Actions environment protections. Unknown manual-dispatch refs do not deploy. Separate scopes no longer replace one another's pending Actions runs; runs targeting the same scope remain serialized together. The Action's source-ref request carries `environment` through the existing API, so no deployment endpoint or webhook behavior changes.
- **Rejected alternatives:** Leaving mapped branches to the App push listener contradicts Actions ownership and is ignored by `production_trigger=actions`. Sending raw branch names as scopes bypasses the project environment registry. Allowing manual dispatch from any branch could route an unconfigured ref into the default environment.
