# ADR-381: Compact platform-tenant statement lines

- **Status:** accepted
- **Date:** 2026-09-30
- **Decision:** Separate the public invoice view from immutable minute coverage. Group public statement lines by app, attributed source, and effective rate-card version; include the earliest contributing minute as `window_start` and the exclusive end after the latest contributing minute as `window_end`. Persist exact minute/source/billable-unit coverage privately and use it to calculate additive revisions. Backfill the new coverage column from existing minute-level lines.
- **Why:** The 20,000-minute-line snapshot ceiling makes active multi-app customers split periods to satisfy an internal representation constraint. Public invoice rows need pricing provenance and quantities, while late-arrival correctness needs minute-level coverage; those are different data shapes.
- **Consequences:** The API no longer rejects a statement because it has more than 20,000 usage minutes. A public line may span gaps; clients must treat its window as a bounding interval, not a minute export. Existing statements remain readable and their coverage is seeded without rewriting their price, units, amount, status, or handoff. The JSONB coverage array and adjustment reads still scale with minute usage, so high-volume qualification must measure storage and load before publishing volume promises. Rate-card changes remain separate lines, and finalization, currency rules, overlap checks, and external handoff semantics from ADR-238/239 remain in force.
- **Rejected alternatives:** Keep the old cap and require customers to choose smaller windows (preserves unnecessary invoice segmentation); infer coverage from compact line ranges (gaps and differing rate periods would overstate prior usage); delete minute evidence after compacting (late usage could be double charged or silently missed); expose every minute publicly (keeps invoice payloads proportional to usage).
