# ADR-1359: Binding verification run diagnostics

- **Status:** Accepted
- **Date:** 2026-10-14
- **Context:** Durable verification and SDK recovery preserve identities, but blocked status combines review changes and expired evidence into generic reasons. CI and operators need actionable explanations without reconstructing server qualification.
- **Decision:** Add read-authorized diagnostics endpoints for app and graph receipts, CLI `diagnostics` actions and typed Go/Node/Python methods. Return original identity/deadline/status, observation time, completeness, current public check result, per-binding blockers, whitelisted public differences and suggested recovery actions. Existing receipt status and generic error contracts remain compatible.
- **Read-only:** Read public inventory and policy for the original selections and inspect stored admission fences. Reconfirm graph membership and prepared manifest authority. Do not capture private task commands, admit work, publish messages, cancel resources, update receipts or renew deadlines. Diagnostics do not authorize future admission, completion or activation; those operations retain their independent fresh checks.
- **Comparison:** Expose policy revisions, modes, evidence age, acknowledgment requirements, configuration timestamps, binding presence/access/state, public credential generations/configuration flags, rotation state, queue capability and exact service target UUIDs. Compare only selected resource scopes, including app-wide service/outbound bindings and shared queue bindings. Omit arbitrary object serialization, policy reason strings, URLs/provider origins, protected pins, credentials, raw errors and guest output. Unclassified protected/snapshot changes receive a generic blocker with no guessed value comparison.
- **Recovery:** Preserve the original run ID. Suggest resumption for frozen unadmitted or pending work, waiting for application acknowledgment/readiness, retrying incomplete diagnostics, or explicit cancellation and a new reviewed receipt when original authority/evidence cannot be reused. Review requirements suppress contradictory resume/wait actions. Incomplete inventory is not interpreted as removed bindings. Missing or forbidden domain access never yields historical protected catalog data.
- **Graph:** Aggregate member diagnostics and recovery under the root receipt. Removed/unavailable members remain explainable; forbidden members fail the entire response. Use current member resource observations when suggesting owned cleanup. Report membership and graph selection/fence changes without modifying routing.
- **Validation:** Pure/public diagnostic tests with capture spies and receipt/task invariance; pending, failed, expired, acknowledgment, policy/configuration/binding drift, partial reads and protected string redaction; graph membership changes; real HTTP read gates and no queue publication; CLI JSON and Go/Node/Python wire contracts; OpenAPI parity and lint.
