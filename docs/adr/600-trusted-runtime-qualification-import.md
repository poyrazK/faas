# ADR-600: Trusted import of exact runtime native qualification evidence

Status: accepted · 2026-10-06

## Context

ADR-599 requires an immutable native receipt before explicit runtime upgrade
preparation, but has no production writer. A generic metal smoke run stages a
synthetic base and cannot qualify an exact published managed function runtime.
An operator-submitted digest or a successful command with skipped tests is also
insufficient. The qualification must bind a native acceptance attempt to the
published base and a managed function layer that actually used it.

## Decision

Add a private operator command, `cmd/runtime-qualification-import`, and the
portable `pkg/runtimequalification` verifier. There is no customer endpoint or
private signing key in the importer. The operator supplies a protected Ed25519
public key, complete release ID, designated host UUID, source/harness commit and
run UUID separately from evidence. The signed envelope contains a version,
SHA-256 public-key identifier and canonical base64 payload/signature. Sign the
payload with the domain `gregale-runtime-qualification/v1\n`. Reject unknown or
duplicate JSON fields, including case variants, trailing values and invalid
UTF-8. Canonicalize the envelope for its retained aggregate report digest.

The `runtime-upgrade-native-v1` report requires Linux amd64, a non-virtualized
host with accessible KVM, exact host/boot/source/run identities, published base
and guest-init digests, deployment/layer identity and digest, kernel and
Firecracker digests, cold boot, HTTP readiness/content, completed retirement,
both explicit zero process exits and a completed acceptance interval.

Require strict raw `go test -json` coverage for exactly
`TestMetalRuntimeReleaseColdBootReady` in `pkg/fcvm`: package start, test run,
one matching observation, test pass and final package pass in interval/order.
Reject skips, failures, unknown actions, unrelated tests, incomplete coverage,
duplicated observations and events after completion. Require signed log digests
and exactly one final successful leakcheck verdict; non-Linux skip/no-op output
and leak/failure markers cannot qualify a release. The protected native signing
owner verifies actual process exits, final leakcheck ordering and physical host
facts. A signature authenticates that owner; parser checks alone do not prove
hardware provenance. `EncodeEnvelope` is a helper for that owner, not a customer
signing service or an automated collector.

Add a metal-only observation test which has no synthetic image fallback. It
measures machine/boot identity, non-virtualized KVM, source commit, exact base,
layer, kernel and resolved Firecracker bytes, and `/sbin/init` from the base.
It boots the separate base/layer drives through the existing native manager,
probes the fixture's known runtime-specific response, destroys the VM, verifies
zero leases/leaks and rechecks artifact hashes before emitting its observation.
The fixture layer must be an existing managed function publication. Missing
fixture selection skips a generic metal suite and cannot satisfy this profile.
The test runs only on the designated, drained, exclusively locked native
acceptance host; host locking, artifact staging, source transfer verification
and protected signing remain the acceptance owner's responsibility.

Before writing a receipt, independently validate the catalogue identity,
managed function deployment/runtime/physical-account binding and streamed
SHA-256 digests of the currently published immutable base and layer. Archive the
canonical signed envelope and original log bytes under
`qualification/runtime-releases/<release>/<report-digest>/`. Read each object
back and verify it before the first ledger write. Identical retained objects
are reused; corrupt retained evidence is rejected and never repaired. A failed
archive can leave unreferenced audit objects but cannot grant eligibility.
The existing ADR-599 store owns immutable retries and permanent revocation.

Central limits in `pkg/api/limits.go` are 64 KiB for report/envelope/fixture
JSON, 64 MiB per captured log, 256 KiB per log event/line and 16 JSON nesting
levels. Published artifacts are hashed as streams rather than buffered.

## Consequences

Only the private importer writes platform qualification metadata. It uses the
existing operator database/artifact configuration, does not run migrations or
VMs, and writes no apps, deployments, instances or traffic. Bad signatures and
incomplete logs are rejected before opening database/storage connections.
Imports retain the exact captured inputs rather than reopening mutable paths.

This closes the trusted ingestion boundary. An automated guarded native
collector/signing runner remains subsequent work. No arm64 acceptance profile
is provided. No real receipt is generated by unit fixtures or local macOS
compilation. Applying/scheduling upgrades remains unavailable; public previews
keep `execution_available=false`. Future candidate acceptance and authoritative
cutover must repeat qualification/baseline checks and serialize against
revocation, as required by ADR-599.

## Validation

Synthetic signed fixtures cover signer/domain/pin mismatch, malformed and
ambiguous JSON, incomplete exits/profiles, skipped/borrowed/truncated test
coverage, log tampering, corrupt/missing published bytes, incorrect bindings,
archive write/readback failures, retained corruption, cancellation, immutable
retries and inability to undo revocation. A real PostgreSQL import test verifies
the production adapter, original recording time, retained revocation and
unchanged customer app/deployment state. CLI tests reject invalid evidence
before opening resources and verify resource cleanup. Native test compilation
is distinct from running it. Dedicated native `test-metal` and final
`leakcheck` remain mandatory before deployment or qualifying an actual release.
