# ADR-1376: Native object-storage starter acceptance

- **Status:** Accepted; native execution pending
- **Date:** 2026-10-15
- **Context:** Both storage starters have portable application-hook and signed gateway coverage. Those tests do not execute the source builder, guest secret delivery, scheduler retirement, Firecracker snapshot or failed-hook cold fallback together. Existing deployed native acceptance covers the Node PostgreSQL starter.
- **Decision:** Add `make test-object-storage-native`, isolated by `metal,object_storage_native`, using the unchanged embedded Node storage source, lockfile, runtime and lifecycle manifest. Add only public fixture trust under the existing runtime COPY, selected through ordinary `NODE_EXTRA_CA_CERTS` application configuration. Use the real API, catalog, sealed compute credentials, source builder, public/internal gateways, scheduler and VM owners. An owned TLS listener wraps the production SigV4 gateway and S3 adapter; an in-memory HTTP provider owns disposable bytes. No production lifecycle, API, schema, quota or admission changes.
- **Journey:** Require eight phases covering deployment and initial restore; fresh same-revision transport; running rotation and resident retirement; parked rotation with scheduler notification recovery; a restore under rotated credentials; a one-shot validation deadline causing failed-hook acknowledgment and cold fallback; external lifecycle-header spoof rejection; and independent revocation/cleanup. Check public application adoption against current versions/process generations, real wake receipts, stale failed/rotated snapshots, byte preservation and exactly one provider PUT per explicit test mutation. Host observer traffic is excluded from guest connection measurements. Read-only observer requests are independently SigV4 signed; current/control credentials must work while retired credentials fail.
- **Evidence and isolation:** Require a designated idle x86_64 Linux KVM host, explicit host class, shared acceptance lock, enabled disposable PostgreSQL, before/after leak checks and an owned benchmark `/32` removed on exit. Fail on missing/skipped/failed phases, absent parent/package passes, artifact changes, dirty/mismatched executable provenance or incomplete cleanup. Fingerprint actual runtime/base bytes and emit a bounded 24-hour report only after cleanup. Preserve private result logs and refuse to replace evidence. Nested diagnostic reports explicitly set `native_qualified=false`; reports are operator evidence, not remote attestation or an automatic rollout gate.
- **Validation:** Portable tests cover exact source packaging/public-only trust, native artifact requirements, verified TLS, retained/disconnected connection observation, one-shot validation cancellation, healthy subsequent validation and the independent observer through the production signed gateway. Test strict evidence rejection and atomic no-overwrite output, and compile the tagged journey in both CI tiers. Supported native execution and host leak qualification remain pending when KVM is unavailable. This fixture does not qualify live providers, public DNS/Internet egress, provider durability or Python guest execution.
