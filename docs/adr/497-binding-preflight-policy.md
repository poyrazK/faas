# ADR-497 · Bindings preflight policy

- **Status:** accepted
- **Date:** 2026-10-02
- **Decision:** Add read-only `gregale bindings check` backed by a deterministic evaluator in `pkg/bindingcheck`. Reuse the existing inventory endpoint and independent verification, runtime freshness and rotation observations. The command makes one GET and exits 0 only when its declared policy passes; blockers, usage errors and read failures exit 1.
- **Why:** Inventory completeness establishes successful reads. It cannot serve as a CI health gate: failed or expired probe evidence, stale serving instances and failed credential refreshes can coexist with a complete inventory.
- **Selection:** Default to the live deployment scope used for manual-task verification. Explicit `--scope` asserts that scope and fails if the selected deployment differs; it does not select another deployment. Check app-wide bindings and managed resource bindings in that scope. Report other resource scopes as skipped. Check all residents in the selected scope, including superseded deployments with remaining residents.
- **Evidence policy:** Require ready supported bindings, passed task-guest evidence matching the selected deployment, scope and PostgreSQL credential generation, complete successful stages and a completion timestamp. `--max-verification-age` is a positive duration, default ten minutes, inclusive at the boundary. Future timestamps, missing, pending, failed, stale or contradictory evidence block. The evaluator accepts an explicit clock and performs no I/O.
- **Runtime and rotation policy:** Stale or unknown residents, starting replacements, missing observations and contradictory counts block. An inactive selected deployment is allowed with an explicit lack-of-adoption warning, preserving scale-to-zero operation. Rotation state must be known. Pending retirement blocks even after a completed handoff; failed, unfinished and unknown handoffs independently block. Probe success and refresh completion never clear runtime blockers.
- **Coverage:** Active queue and outbound bindings block as unsupported by default. An explicit `--allow-unsupported` waiver turns only those coverage blockers into warnings, retaining `unsupported` per-binding status and `partial` coverage. Disabled bindings and managed resources outside the selected scope are skipped. Unknown binding families remain blockers under a waiver. No active selected bindings yields `none` coverage and a warning.
- **Reports:** Human diagnostics give remediation; JSON exposes applied policy, scope, deployment, per-binding status, runtime counts, inventory issues and stable blocker codes. Lists are present even when empty. The evaluator does not mutate the inventory. No new API endpoint, database schema, executor, guest probe or lifecycle mutation is added.
- **Limits:** Best-effort point-in-time observations are not a transaction fence for promotion, application readiness or proof of credential adoption. Runtime freshness uses admission timestamps. Object-storage evidence establishes bucket-list read access only. Integrating this policy into promotion requires a separate design for authoritative deployment identity and concurrent configuration changes.
