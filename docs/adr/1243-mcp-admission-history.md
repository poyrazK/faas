# ADR-1243: Searchable retained MCP admission evidence

Exact receipt lookup is account-bound and independent of the recent generic audit window. Deployment history filters MCP rows before limiting and uses descending audit sequence keyset pagination. Concurrent new rows cannot shift subsequent pages; retention may remove older rows. Cursors are continuation positions, never authorization credentials. Both queries join current deployment/app ownership and retained audit account ownership. Existing retention and deletion semantics remain unchanged.

The CLI supports `mcp access history --deployment UUID --outcome rejected --limit 50`, subsequent `--cursor` pages, and exact `--evidence UUID`. Convergence alerts link the exact receipt. Status and overview now consume the first MCP-only page and independently request the latest accepted and rejected receipts with outcome filters and limit 1. This bounds read work while preserving visibility of an older outcome beyond the first page. Each outcome carries its own available, empty, or unavailable state; read failures do not change protocol health. The legacy window_limit JSON field remains for compatibility and now counts MCP receipts.

`mcp access explain --evidence UUID` derives diagnostics from the retained receipt, including freshness relative to captured_at and replay relative to observed_revision. Optional --app verifies deployment ownership before fetching a separately timestamped current account-convergence snapshot. Unknown or missing evidence remains unavailable; an accepted historical decision never implies current fleet health. No automatic retry or application call is performed.
