# ADR-1645: Binding verification for reviewed source builds

- **Status:** accepted
- **Date:** 2026-10-17
- **Decision:** Use one private immutable artifact revision for managed HTTPS probes, push-worker queue canaries and single-app durable verification runs. Support already-admitted source, Dockerfile and function deployments with frozen reviewed source archives; retain existing workload-class restrictions.
- **Artifact identity:** Hash the canonical rootfs key and size, deployment kind, real OCI digest where present, build ID, archive location/checksum/size, source root, commit, build-log location, handler, deployment environment and frozen reviewed inputs. Validate source/build fields through `ScopedWorkloadRuntime` before computing the revision. Source builds require a materialized rootfs with positive size. Never invent an OCI digest or infer review from mutable app defaults. Both PostgreSQL and memory paths use this contract.
- **Authority:** Retain exact active release membership, environment, source mode/generation, held state, binding contract, service-policy and binding release-policy fences. HTTPS context covers both caller and target artifacts. Queue snapshots and durable-run authority include the same artifact revision. Rebuilds, including self-consistent replacement provenance, invalidate prior evidence; SQL JSONB normalization does not.
- **Tasks:** Admit and restore an empty-digest source artifact only for a current managed service binding probe. Ordinary tasks retain their image-only eligibility. An append-only migration permits that task shape only with matching deployment, scope, service, target and context-revision pins. A downgrade refuses to discard source-probe history. Existing applied migration bytes remain unchanged.
- **Existing receipts:** The private artifact/context revision changes for images too. Existing short-lived receipts must be refreshed; no historical receipt is silently upgraded.
- **Consent and bounds:** Keep explicit `--queue-publish`, reviewed handler capability, one message/attempt, no replay, the original deadline, quota checks, cancellation and exact handler acknowledgement. No public API or SDK field changes are needed; artifact details remain private.
- **Acceptance:** Portable tests cover source/Dockerfile/function HTTPS callers and source targets, archive/build/rootfs drift, stale completion evidence and durable admission. PostgreSQL exercises reviewed source and Dockerfile graphs, task constraints, replay, handler completion, live-rootfs immutability, source suspension and a fresh source-graph replacement. Enforced app binding release policy remains an independent gate and is never disabled for a rollout. Managed-service native contract version 4 adds a real Dockerfile-built worker, strict HTTPS plus queue CLI verification, and source rebuild/release invalidation. Its archive, provenance and built layers enter the retained artifact manifest. Compile-only and owner-API fixtures do not provide native qualification.
- **Limits:** Unreviewed legacy source archives, pull queues, jobs and other unsupported classes stay unsupported. Project-wide durable graph verification retains its existing managed-workload restriction. [ADR-1646](1646-candidate-binding-qualification.md) provides a separate qualification-owner path for supported held candidate cohorts. Real native `test-metal` and `leakcheck` qualification remains required on a dedicated x86_64 Linux KVM host.
