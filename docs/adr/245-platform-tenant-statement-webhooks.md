# ADR-245 · Durable webhooks for platform tenant statements

- **Status:** proposed
- **Date:** 2026-09-25
- **Decision:** Let an account create signed outbound webhook subscriptions scoped to one platform tenant for the closed event `platform_tenant.statement.finalized`. Enqueue one durable delivery per subscription and immutable statement revision in the database transaction that changes the statement to `finalized`; use the existing webhook retry ledger, signing scheme, delivery inspection, and dead-delivery retry. Represent the tenant as the event source and leave the delivery's app ID null.
- **Why:** A platform tenant can combine usage from multiple Gregale apps into one payable statement. App-scoped hooks would fan this single billing fact out as duplicate per-app events, and best-effort enqueue after finalization could leave a finalized statement without an event after a crash.
- **Consequences:** The account-level webhook quota is shared with app and account release subscriptions. Each receiver belongs to one tenant, accepts only the finalized-statement event, and has a unique target URL within that tenant. The payload contains the immutable complete revision, including line provenance and the stable external customer reference. Existing webhook retry behavior means delivery is at-least-once; receivers should deduplicate by delivery ID. Subscriptions are not backfilled for already-finalized statements. The API, OpenAPI and AsyncAPI contracts, Go SDK, and tenant onboarding docs expose management and replay. This emits billing facts but does not issue invoices, collect payment, or alter statement handoff semantics.
- **Rejected alternatives:** Per-app subscription fanout (creates multiple callback events for one cross-app invoice); enqueue in the API handler after finalization (not atomic with the state transition); add a separate webhook queue/secret/signature scheme (duplicates durable delivery and security machinery); emit invoice-ready events for draft statements (pricing and immutable payable totals are not yet established).
