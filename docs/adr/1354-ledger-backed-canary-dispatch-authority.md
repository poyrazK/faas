# ADR-1354: Ledger-backed canary dispatch authority

- **Status:** Accepted
- **Date:** 2026-10-14
- **Context:** Queue completion canaries added an app read and a canary read to every canonical invocation's version resolution. Ordinary durable dispatch already reads the app and persisted environment owner, making these extra round trips unnecessary.
- **Decision:** PgStore and MemStore expose a private combined dispatch authority read: persisted environment, app and account ownership plus canary membership. PostgreSQL uses the existing invocation row and an indexed membership existence check. Version resolution loads the app once, uses this combined read in place of its first environment-owner read, and fetches full canary evidence only for registered canaries. Later environment and work-admission checks remain fresh reads.
- **Authority:** A source, payload, header or caller-supplied boolean cannot certify canary membership or its absence. Canary admission creates a unique invocation and its membership in the same transaction; ordinary invocation IDs cannot be enrolled through the public API. Membership includes cancelled and expired records. Missing or unavailable evidence for a registered canary fails closed. A registered canary cannot dispatch under a different app/account or use ingress resolution to bypass the durable gate.
- **Compatibility:** Store adapters without the private authority capability retain the conservative canary lookup using the already-loaded app. Synthetic trigger and workflow correlation IDs keep their existing paths. No schema migration, public API, SDK, capacity grant or lifecycle change.
- **Validation:** Ordinary async invoke, webhook, queue, delayed task, cron and replay read budgets; actual PostgreSQL query tracing; live canary dispatch; cancellation, expiry, attempt/replay/pin fences; changed source/payload and ownership; missing/error authority; legacy adapter fallback; existing invocation environment and revision isolation tests. The optimization removes two separate reads from ordinary canonical dispatch; it does not assert a measured latency gain.
