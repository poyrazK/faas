# ADR-1375: Node object-storage starter recovery

- **Status:** Accepted
- **Date:** 2026-10-15
- **Context:** The existing Node storage starter owns adoption and streaming leases but has no explicit application barrier for rebuilding captured transports after snapshot restore. The PostgreSQL and Python storage starters already provide bounded restore recovery.
- **Decision:** Add the existing two-second after_restore hook and a manifest selecting `/readyz`. Authenticate the actual loopback peer plus `X-Faas-After-Restore: 1`, independently of bearer authentication and forwarded headers. Reuse the canonical Node coordinator's per-attempt cancellation and the managed storage binding's invalidation/retirement lifecycle without changing SDK APIs or vendored runtime implementations.
- **Recovery:** Immediately close readiness, fence the captured client and abort captured transfers. Within a maximum 1.5-second application budget, reread the latest snapshot even at an unchanged revision, validate a fresh S3 transport and HTTP token, and drain captured body/spool leases before reopening. Coalesce concurrent hooks; owner cancellation aborts shared recovery, follower cancellation only ends its wait. Failed/cancelled/timed-out recovery remains closed through ordinary SIGHUP until successful recovery, preserving the platform cold-boot fallback. Queued/active cancelled validation cannot publish a candidate or initiate an applied ACK later. An already initiated ACK cannot be recalled, and adoption ACKs do not certify captured-resource drain completion.
- **Transfers/shutdown:** On abort, close captured HTTP connections promptly while late provider results remain owned by the existing transfer promise and lease. Check cancellation before provider operations, before download headers and after uncertain PUT return. Await actual Node body/file close events before releasing leases or removing staged files. Do not replay operations or forcibly retire leased clients. Terminal shutdown aborts recovery, stops reloads/admission and preserves the existing five-second graceful-drain budget. Keep that deadline referenced until completion so an otherwise idle process still reports an incomplete drain.
- **Validation:** Extend exact embedded-artifact tests for manifest readiness/hook settings, peer/header authorization, same-revision replacement, partial upload/held download cancellation, late GET/PUT and delayed close ownership, cancelled/queued adoption, coalescing, owner/follower disconnects, sticky failure, subsequent recovery and shutdown. Extend the existing real AWS SDK/production SigV4 gateway/S3 adapter/MemStore/provider-fixture journey to observe a fresh gateway connection at the same revision, captured provider cancellation without replay, failed validation, active/queued hook timeout and recovery. Keep canonical runtime drift and existing transfer/revocation tests in CI. No guest/hypervisor lifecycle source, server API, schema or quota changes; portable application-hook evidence does not replace native VM snapshot or live-provider qualification.
