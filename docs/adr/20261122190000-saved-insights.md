# ADR 20261122190000 · Saved insights: share, export, digests and threshold alerts

- **Status:** accepted
- **Date:** 2026-11-22
- **Amends:** ADR-20261117084505 (product analytics)

This record has a date-and-time identifier because numbered ADRs collide
when parallel changes pick the next number.

## Context

Product analytics (ADR-20261117084505) answers ad hoc event series, funnel
and retention queries. A query lives only in the command that ran it: a
teammate cannot rerun it, nobody hears when its number moves, and the data
cannot leave Gregale except as JSON from the CLI.

The owner chose before this record:

1. **Scope:** save, run and share; CSV and JSON export; scheduled digests;
   threshold alerts.
2. **Release:** dark, behind a platform flag.

## Decision

### 1. A saved insight is an environment's named query with a relative range

`saved_insights` holds, per project environment, a key (the flag key
shape), a display name, a kind (`events`, `funnel` or `retention`), the
kind's request without `from`/`until`, and `range_days`. Every run covers
the last `range_days` days, clamped to the plan's analytics retention, so a
saved insight never goes stale. 50 per environment
(`SavedInsightsMaxPerEnvironment`).

Its **value** is one number: an events insight's total (events, or the sum
of values with `measure: value`), a funnel's overall conversion (last step
from first), a retention query's first-period rate. Digests report it and
alerts compare it.

### 2. Sharing follows project access

Saved insights are not owned by a person. Anyone who can read the project
lists, gets and runs them (`OrgActionReadProject`); saving, replacing and
deleting one needs deploy rights (`OrgActionDeployProject`), like a cohort.
Routes, under `/v1/projects/{slug}/environments/{environment}/insights/saved`:

| Route | Does |
| --- | --- |
| `GET /` | list, with last value and alert state |
| `POST /` | create |
| `GET /{key}` | one saved insight |
| `PUT /{key}` | replace definition and schedule |
| `DELETE /{key}` | delete; digests and alert stop |
| `GET /{key}/run?format=json\|csv` | run now; CSV is an attachment |

The CLI is `gregale insight saved list|create|get|run|delete`; `run --format
csv` renders the same CSV locally from the JSON result.

### 3. CSV shape

One row per point of an events series (`start,breakdown,events,units,value`),
per step of a funnel and of each breakdown
(`breakdown,step,event,units,conversion_from_first,conversion_from_previous`),
and per period of each retention row
(`cohort,breakdown,period,eligible,returned,rate`). Both apid and the CLI use
`api.WriteSavedInsightCSV`.

### 4. Digests and alerts run in meterd and use notification channels

A saved insight may set `digest` (`daily` or `weekly`), an `alert`
(`gt`, `gte`, `lt` or `lte` a threshold) and up to 5 notification channel
IDs of its account; a digest or alert needs a channel. meterd holds the
alerting seal domain that opens channel destinations, so it runs them, not
apid:

- Due rows are leased (`next_check_at`, `lease_until`, `FOR UPDATE SKIP
  LOCKED`), 10 per pass every minute. The lease covers every item's query
  timeout; an item the lease no longer covers is released for the next pass.
- Digests go out at 08:00 UTC, weekly ones on Mondays. A digest is a report,
  not an incident: it is a new `digest` channel event and is never sent to
  PagerDuty.
- Alerts are checked every 15 minutes. A transition to breaching sends a
  fire, a transition back a resolve (one PagerDuty incident per saved
  insight). A failed query keeps the alert state, records `last_error`,
  sends nothing and retries in 15 minutes; a due digest stays due until a
  run succeeds. A value with no data behind it (a funnel without entrants,
  retention before a period has ended) is absent and leaves the state alone.
- A settle only applies if the row is unchanged since its claim, so an edit
  during a run keeps its new schedule; notifications go out only after the
  settle applies. Changing the query, range or alert resets the state to
  `ok`.
- Notifications carry no console link: the console has no saved insight
  page yet. They name the CLI command instead.
- A channel deleted later is skipped; it does not block the channel's
  deletion.

These are not alert rules: alert rules are app metrics evaluated from
Prometheus and the log ledger, while a saved insight reads analytics events
per environment. Reusing the channels keeps one place to manage
destinations.

### 5. Release

The `saved_insights` platform flag (capability `saved-insights`, parent
`product-analytics`, internal) gates the routes. meterd runs a saved insight
only while its account is live and has both capabilities; otherwise it
records why, sends nothing and looks again an hour later. Rows are kept.

## Consequences

- One more meterd loop; each pass runs at most 20 bounded analytics queries
  (15 s timeout each).
- A value is a total over the range, not a rate per period; alerting on a
  daily count means a 1-day range.
- Deferred: a console view, per-person private insights, alerting on a
  breakdown value, digests with a chart.
