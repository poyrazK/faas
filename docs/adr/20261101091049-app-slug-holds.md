# ADR 20261101091049 · Hold a renamed or purged app's slug for its account

- **Status:** proposed
- **Date:** 2026-11-01
- **Amends:** ADR-095 ("the slug is free for reuse" after a preview's teardown
  now means free for the same account), the app rename route
  (`POST /v1/apps/{slug}/rename`) and the app purge after the 7-day restore
  grace (`api.AppDeleteGraceDays`).
- **Related:** bug hunt 2026-10-28 H80

This record has a date-and-time identifier because numbered ADRs collide
across parallel branches.

## Context

An app's slug is its public host on the apps domain. `apps.slug` was the
only uniqueness check, so a rename freed the old slug the moment it
committed, and a purge freed a deleted app's slug once the row was removed.
Any other account could then create an app with the old name and receive
everything still pointing at the old host: bookmarks and links, third-party
webhooks the customer registered (Stripe, GitHub and similar send event
payloads, often with personal data), OAuth redirect URIs registered with
identity providers, and browser cookies the original app set on that host.
PR previews (`pr-<N>-<slug>`) are torn down and purged often, so their links in
the original repository's pull requests were exposed the same way.

## Decision

1. **Holds.** A new table `app_slug_holds` (slug, account, `held_until`,
   reason `renamed` or `purged`) records a slug when a rename moves an app
   off it or a purge removes its row. The hold lasts
   `api.AppSlugHoldDuration` (90 days). A later rename or purge of the same
   slug replaces the hold.
2. **Enforcement in the database.** Triggers on `apps` record holds (after a
   slug update or a delete) and refuse an insert or slug update to a slug
   another account holds, raising the same `apps_slug_key` unique violation
   a taken slug raises. Every writer, older releases included, sees a held
   slug as taken; no API changes shape.
3. **The owner keeps it.** The account the slug is held for may create or
   rename an app to it at any time, which covers recreating a preview or
   undoing a rename.

## Consequences

- Another tenant cannot take over a renamed or purged app's host for 90 days.
- The old host answers as an unknown app during the hold; it does not yet
  redirect to the new slug. A 308 redirect from the old host and an early
  release of a hold on the owner's request are follow-ups.
- A slug held for an account that is later erased stays held until the hold
  ends.
- MemStore mirrors the triggers so unit tests see the same rule.
