# ADR-1362: Reviewed verification creation helpers

- **Status:** Accepted
- **Date:** 2026-10-15
- **Context:** Existing runners recover a receipt, but SDK users manually assemble review digests, selections and consent at creation. A lost create response must remain recoverable before any runner starts. CLI creation errors previously omitted machine-readable identity.
- **Decision:** Add app and project create-from-review helpers in Go, Node and synchronous/asynchronous Python. Require an explicit previously obtained review, a caller-supplied canonical nonzero UUID and an explicit lifetime. The caller persists this UUID before invoking creation. Validate readiness, selectors, member coverage/digests and required consent locally, then forward opaque server digests unchanged. Server review freshness, permissions and atomic idempotency remain authoritative.
- **Recovery:** Typed creation errors retain the UUID, original cause and whether creation was invoked. This flag does not prove server acceptance. Never retry creation or generate another identity automatically. Separate reconciliation helpers perform exactly one GET at that UUID; they validate the reviewed selection, original lifetime, consent, concurrency, plans and graph membership before returning the receipt. Missing, unavailable or mismatched reads remain errors and never establish that creation did not happen. Reconciliation also accepts terminal and expired receipts; it neither resumes nor renews them.
- **Cancellation:** Go context and Node abort signal stop requests; a pre-cancelled call does not invoke creation. Python preserves native asyncio cancellation with receipt identity and attempt metadata. No helper admits steps, executes recovery suggestions, cancels server work or activates routes. Call an existing runner explicitly after a confirmed creation/reconciliation.
- **CLI:** Durable app and project creation use the same Go helpers. JSON failures include `run_id`, app or project/environment, `passed=false`, `status=creation_failed`, `create_attempted`, the original error and inspection guidance. Plain errors retain the identity. No automatic creation reconciliation or cleanup is introduced.
- **Compatibility:** Generated low-level methods remain available. Go canonical sources synchronize into the leaf SDK; Python generation preserves the helper and public exports. No endpoints, OpenAPI, server state or database changes.
- **Validation:** App/graph lost responses followed by one read-only reconciliation; zero writes for invalid identity/readiness/consent/lifetime/budget; mismatched selections, plans and original expiry; original error chains and cancellation; CLI JSON/plain failure contracts; SDK compilation, source synchronization and Python generation preservation.
