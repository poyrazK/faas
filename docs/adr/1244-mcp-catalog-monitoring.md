# ADR-1244: Opt-in continuous MCP catalog monitoring

An app-scoped, reviewed format-2 baseline is configured through apid with deploy-write authorization. Apid is the sole writer of monitor intent and retained receipts. A supervised observer runs `gregale mcp monitor run`, using its MCP role token only for initialize and catalog discovery and a separate platform credential with read and metrics-write scopes for reporting. Meterd reads stored observations and never probes a customer application or decrypts its MCP role token.

Configuration issues a new revision, resets current evidence, and preserves recent transition history. Apid canonicalizes contracts and computes strict diffs. Reports carry the reviewed revision; a transaction locks the owning app and monitor before accepting a report, so in-flight probes cannot overwrite a newer baseline or disabled monitor. Server receipt and heartbeat timestamps cannot be supplied by observers. Observers are trusted telemetry publishers, not cryptographic attestations of role identity or every replica.

The last 32 transition receipts survive observer restart and retain bounded difference paths, counts, hashes, and recovery state. Repeated equal state/catalog observations refresh checked_at without duplicate receipts. Differences are capped at 128 changes and 64 KiB; truncated receipts preserve the full change count. Configuration and observations are bounded to 1 MiB. App/account deletion cascades these rows. This bounded history is not permanent archival storage.

Notification-only metrics mcp_catalog_drift and mcp_catalog_monitor_unavailable reuse alert claim deduplication, cooldown, delivery retention, and recovery. Drift is unknown for absent/stale/future-dated/failed observations. Unavailability fires for an enabled monitor without fresh valid observations; disabled or unconfigured monitors are paused. Source read errors are degraded. No rules are enabled automatically and no deployment actions are allowed. Payloads link retained receipts and include counts, not catalog definitions or credentials. Window specifications do not impose a sustained breach window on these instantaneous observations.

The observer uses sequential bounded probes and separately bounded reports, retaining no raw probe errors. Platform reporting failure or revision conflict stops the process so its supervisor can restart it; source failures are reported unavailable and retried on the next interval. Polling a scale-to-zero app can wake it and incur runtime usage, so this is explicit opt-in. One supervised observer and one reviewed authorization view per configured app are supported.
