# ADR-1374: Python object-storage starter recovery

- **Status:** Accepted
- **Date:** 2026-10-15
- **Context:** Async object-storage binding ownership and mixed PostgreSQL/storage adoption exist, but the Python storage example requires a repository-relative SDK install and has no private HTTP API, deployable scaffold or application restore recovery. Captured HTTP transports and unfinished transfers need explicit recovery after VM restore.
- **Decision:** Add `object-storage-python` as a first-class stateless-contract CLI starter. Vendor the canonical async storage/coordinator import closure, explicitly embed private Python modules, check drift and package isolation, pin application/transitive dependencies and run one unprivileged Python 3.12 process. Generalize the existing Python starter synchronizer without changing SDK runtime behavior.
- **Adoption/authentication:** Adopt explicit `GREGALE_S3_ASSETS` settings and `STORAGE_APP_TOKEN` from the modern atomic snapshot/readiness/ACK/generation contract. Validate each fresh transport with ListObjectsV2(MaxKeys=1), then validate token policy before the applied ACK. Any failure or revocation disables both consumers. Use managed `read_write` permissions; the list probe is evidence of list access, not write capability or continuous provider availability. Configure SigV4, path addressing, required-only checksums, verified TLS, finite driver waits and one driver attempt without ambient credentials/tokens/proxies.
- **Transfers:** Bearer-authenticate PUT/GET for simple private object identifiers. Serve opaque attachments with nosniff. Stage uploads in 0700 directories and 0600 files, enforce exact lengths and a 10 MiB cap, allow two uploads and 16 total transfers, and apply a 30-second total application budget. These are sample application safeguards, not platform quotas. Retain owned tasks, spools, response bodies and binding leases until actual driver return, including after HTTP cancellation/deadline. Close bodies and files before lease release. Never replay transfers or uncertain writes. Exclude raw driver diagnostics and credentials from public errors/logs.
- **Recovery/shutdown:** Use the existing two-second after_restore hook with a maximum 1.5-second application budget. Authenticate the actual loopback peer and restore header with proxy-header trust disabled. Immediately close readiness, fence the captured transport and cancel captured transfers. Always reread/rebuild, including at an unchanged secret revision, validate the fresh transport and drain captured ownership before reopening. Coalesce hooks; timeout, disconnect or owner cancellation fence late publication/ACK initiation and keep readiness closed until successful recovery, preserving platform cold-boot fallback. SIGTERM/SIGINT stop admission/reloads and allow five seconds for graceful drain, then cancel outstanding application work without forcibly retiring leased clients.
- **Validation:** Test exact materialization, CLI catalog/next-step/required-secret guards, canonical runtime closure and standalone imports. Portable lifecycle tests cover authentication, private spools, byte/capacity limits, held transfers across rotation, late results, disconnect/deadline ownership, same-revision/coalesced restore, active/queued timeout recovery, failed adoption and shutdown. Real aiobotocore acceptance verifies SigV4 and exact bytes against an owned S3 HTTP fixture, stale credential rejection, uncertain PUT/truncated GET without replay, and the actual handler subprocess with SIGHUP, HTTP recovery and graceful SIGTERM. Wire materialized acceptance and dependency isolation into CI. No server API, schema, quota, guest or hypervisor changes. Portable application-hook tests do not qualify deployed providers or native VM snapshots. Node storage restore recovery remains a separate focused follow-up.
