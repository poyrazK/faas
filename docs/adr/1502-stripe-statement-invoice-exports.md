# ADR-1502: Export usage statements to the customer's own Stripe

- **Status:** accepted
- **Date:** 2026-10-11
- **Decision:** An account can store one Stripe key (`PUT /v1/account/billing-connections/stripe`). A finalized app consumer or platform tenant statement can then be exported (`POST …/usage-statements/{id}/stripe-invoice`) as a draft invoice in that Stripe account. The export recording sets the statement's handoff to the Stripe invoice ID.
  - **Key handling.** The key is checked against Stripe, then sealed with apid's age identity under a per-account namespace. Only its last four characters and mode are ever returned or logged.
  - **Customer.** The Stripe customer is the request's `customer`, or else the consumer's or tenant's `external_ref` when it is a `cus_…` ID.
  - **Lines.** The invoice has one item per price source and unit price: free allowance units at 0 and each ladder step at its price. Amounts are converted from millicents to cents, rounded half away from zero. One rounding item makes the invoice total equal the statement total rounded to the cent.
  - **Draft only.** The draft is never finalized or sent (`auto_advance=false`), and other pending items on the customer are excluded.
- **Why:** Statements stopped at a provider-neutral handoff: operators retyped totals into their billing system and recorded an invoice ID by hand. A draft invoice in the operator's own Stripe closes that step, while Gregale never holds or moves the money.
- **Consequences:**
  - **Resumable without duplicates.** An export row (`usage_statement_invoice_exports`) is written before any Stripe call.
    - The invoice's idempotency key is derived from the row, and its ID is stored as soon as Stripe returns it.
    - Each item carries `metadata[gregale_line]`. A retry lists the invoice's items and creates only the missing lines, so a crash or Stripe failure at any point resumes the same invoice. This holds beyond Stripe's 24-hour idempotency window.
    - The handoff is recorded last; the export completes only when the handoff names the invoice.
  - **Handoff rules unchanged.** Exporting is a handoff with a Stripe invoice ID. A statement already handed off to another invoice cannot be exported (409), and the existing overlap rules between app and tenant statements apply.
  - **Currencies and limits.** Only two-decimal currencies are supported; zero- and three-decimal currencies return 422. An invoice has at most 249 lines plus rounding. Statements group per-minute buckets by price, so real statements stay far below that.
  - **Adjustments.** An adjustment revision exports as its own invoice. A re-rated adjustment (ADR-951, ADR-975) can contain negative items, which Stripe accepts on draft invoices. The invoice total is never negative.
  - **Owner and egress.** apid owns the customer-intent tables and makes the Stripe calls synchronously. This is outbound HTTPS to `api.stripe.com` with the customer's key, separate from Gregale's own Stripe billing client.
  - **Switching modes.** An export started with a test-mode key cannot be finished with a live key (409). Reconnecting the original key finishes it.
- **Rejected alternatives:**
  - Finalizing and sending invoices automatically would make Gregale responsible for customer-facing billing actions and errors. Drafts keep the operator in control.
  - Stripe Connect OAuth needs a registered platform and redirect flow. A restricted key is enough for one account's own invoices.
  - Exporting asynchronously from a worker adds a queue for a call that completes in seconds, and the export row already makes retries safe.
  - Other providers (Paddle, Chargebee, Lago) can reuse the connection and export tables, whose provider column is constrained to `stripe` for now.
