# ADR-1026: Later eligibility observations for workflow failures

Accepted, 2026-10-12.

ADR-1025 captures failures outside policy filters, but a terminal failure alone does not prove a recovery parent or a safe retry. Observe retained state independently of policy existence or enabled state. Reuse resume diagnostics and operation ownership checks. A qualifying parent must be a terminal, same-account/app/workflow recovery job with a queued item and saved failed result for the exact run/generation. Choose the newest matching parent deterministically. Generation zero has no saved recovery parent.

The minute scheduler checks at most 100 failures within a five-second request budget. Unchecked failures precede the oldest checked rows; refresh no sooner than five minutes. PostgreSQL claims one row per repeatable-read transaction with `FOR UPDATE SKIP LOCKED`; memory uses its mutation lock. PostgreSQL serialization conflicts retry up to four transaction attempts within the same five-second request budget; exhausted conflicts roll back and retry on a later tick. A failed diagnostic inspection records `inspection_error`, with no raw error text; a PostgreSQL savepoint prevents a failed diagnostic query from poisoning its observation transaction. Database availability and commit errors roll back and retry on a later tick.

Keep one latest typed observation per retained inventory entry, so refresh cannot grow storage. The observation records its own timestamp, parent identity when retained, reason and blocker codes. It contains no run input/output, errors or definition snapshots. Refresh replaces the previous later observation; this is a bounded latest-state diagnostic, not an immutable history of all inspections. It shares the inventory's 30-day/10,000-entry per-app lifecycle, survives run pruning and restarts, and disappears with inventory expiry or app deletion. Downgrade refuses retained observations.

Historical failure candidates retain their failure timestamp and unknown failure-time preflight. Evaluation exposes `later_eligibility` separately, with policy filters applied to the later check. Checks older than 15 minutes are stale and cannot qualify. A fresh positive result means eligible at that observation, not current execution authorization. Preparation, budgets and admission remain unknown; later observations never charge historical replay budgets or change historical totals. This observer does not create policies, reviews, jobs, notifications or retries. Review-backed candidates continue using their captured review evidence.

The bounded global queue may fall behind when failures or retained inventories exceed its capacity. Missing and stale checks stay explicit; no completeness claim is made. This step does not broaden saved-failure automatic execution to initial failures.
