# ADR-1372: Python PostgreSQL starter recovery

- **Status:** Accepted
- **Date:** 2026-10-15
- **Context:** Native async binding lifecycles exist, but Python applications still need container packaging, CLI scaffolding, release isolation and application-level reconnect behavior for captured database sockets. The Node PostgreSQL starter already has these deployment/recovery guarantees.
- **Decision:** Add `rest-api-postgres-python` as a first-class stateless-contract CLI starter. Bundle a complete static import closure of the canonical Python runtime under a private `runtime` package, with synchronization/drift and isolated-package checks. Explicitly embed private Python module filenames. Pin runtime dependencies without repository-relative SDK installs, and use a single-process unprivileged Python 3.12 image.
- **Adoption:** Require the full modern atomic snapshot/readiness/ACK/generation contract. Use `AsyncSecretReloadCoordinator` and `AsyncPostgresPoolBinding` for startup, SIGHUP, manual reloads, validation, leases and retirement on one event loop. Read the existing public notes schema before publication/ACK or HTTP serving. Reject migration credentials in serving environment/snapshots. Upgrade managed TLS modes to hostname/chain verification with explicit system/private-CA trust.
- **Requests:** Bound request work and pool admission, use transaction-local statement timeouts and read-only transactions for reads, retain leases through complete driver connection return, and cancel work on HTTP disconnects. Retain late driver tasks/pool ownership after caller timeout/cancellation. Never replay writes or uncertain COMMITs. `/healthz` is schema-backed database readiness.
- **Restore:** Preserve the platform's two-second hook and a maximum 1.5-second application budget. Authenticate the actual loopback peer plus the restore header with Uvicorn proxy-header trust disabled. Immediately close readiness, fence the captured pool and cancel captured requests. Reread the latest snapshot even at the same revision, validate a fresh pool, drain captured resources, and reopen readiness only on success. Coalesce concurrent hooks; cancel/fence failed and timed-out queued/active adoption without late publication/ACK initiation. A failed hook keeps readiness closed until successful recovery, allowing the existing platform cold-boot fallback. Cancellation cannot retract an ACK already sent or committed SQL.
- **Release/shutdown:** Apply the notes schema only in a separate release command using managed migration credentials, direct connections, advisory-lock serialization and bounded SQL/lock waits. Stop request admission/reloads before a bounded coordinator/pool drain; a timeout never forcibly closes a leased transaction. Do not change guest, hypervisor, server APIs, schemas or platform quotas.
- **Validation:** Test exact materialization and complete runtime packaging, CLI catalog/next-step/secret guards, TLS and migration boundaries, HTTP authorization/disconnects, late connection/validator cleanup, same-revision/coalesced restore, caller cancellation, shutdown and queued/active timeout recovery. Real TLS/SCRAM PostgreSQL acceptance uses the exact embedded app/migration command with restricted roles, an open write across password rotation, old-credential rejection, revocation, stale sessions, missing-schema recovery, real SIGHUP and ACK transport. Wire SDK drift/package checks and materialized SQL acceptance into CI. Portable application-hook evidence does not replace native microVM acceptance.
