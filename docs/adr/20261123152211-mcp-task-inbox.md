# ADR-20261123152211: Discover retained MCP Tasks from a fresh client

Date: 2026-11-23
Status: Accepted

## Context

Durable Task IDs and submission receipts let an agent resume known Tasks.
A fresh client can have the correct credential and still lack both handles.

## Decision

- The Node PostgreSQL starter advertises `io.gregale/task-inbox` and serves
  `gregale/tasks/inbox` on modern external OAuth endpoints. The capability
  requires the additive index installed by the existing schema-owner
  migration command.
- Query only metadata for the caller's namespace, owner hashes, current
  tool policy and unexpired rows. Apply every predicate before pagination.
  Requests perform no queue mutations or payload reads.
- Order by descending expiry and UUID. Sign continuation cursors over the
  precise PostgreSQL anchor, namespace, caller identity and status filter,
  so pagination can continue after a prior row expires. Access is evaluated
  on each page. Pages default to 20 entries and are capped at 50.
- The CLI exposes the result through `gregale mcp client inbox` and returns
  the same next-action metadata as receipt-based status. Clients use the
  returned ID with the existing Task methods for any follow-up.

The [keyed submission contract](20261121213156-keyed-mcp-task-submission.md)
keeps its own replay rules and does not depend on the inbox index.

## Node SDK preview

The Node SDK can list inbox metadata and watch it through an authenticated
official MCP client connection. The caller supplies the connection and
controls its credentials. The SDK checks the negotiated revision and
advertised extensions, then validates the returned metadata, filter, and
cursor. The watch publishes entries only after a complete bounded scan.
Each iterator keeps its own in-memory history and can cancel an outstanding
read through the connection.
