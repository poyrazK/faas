# ADR-20261107210000: `gregale dev --local` runs functions on the developer's machine

Date: 2026-11-07
Status: Accepted (owner decisions, 2026-11-07)
Related: ADR-1170 (developer watch mode), ADR-999 (streaming), ADR-1342
(concurrent workers), ADR-20261107193000 (config in code)

## Context

`gregale dev` uploads the working tree, builds it in a builder microVM and
deploys it to an isolated developer app. That is faithful but each edit costs
a build: seconds to minutes. Function authors want an edit-and-retry loop
measured in milliseconds, with the same handler contract as production.

The handler contract is implemented by two pieces: the generated Node and
Python adapters (`pkg/rootfs`), which load the customer module and speak the
§4.9 envelope protocol, and the runner core (`guest/runners/internal`), which
turns HTTP requests into envelopes and keeps adapters alive in a worker pool.
Neither depends on Firecracker.

## Decision

1. **Same code as production.** `gregale dev --local` runs the platform's
   own adapters and runner core on the developer's machine:
   - The adapter sources move to `pkg/fnadapter` (no behaviour change);
     `pkg/rootfs` aliases them.
   - `guest/runners/local` exposes the runner core (`internal.Serve` and the
     worker pool) to the CLI, which Go's internal-package rule would
     otherwise forbid.
   - Node and Python run with the machine's `node` and `python3`. Go
     functions are built with the machine's `go` and run as the go124 runner
     runs them.
2. **A local HTTP server.** Every function of the project is served on one
   port (default 8787):
   - each at `http://<name>.localhost:<port>`, as each has its own host on
     Gregale;
   - with an `entry: true` function, `http://localhost:<port>` routes like
     the entry address: `routes:` globs first, everything else to the entry;
   - a project with one function serves it at `http://localhost:<port>`.
   The server sets the trusted platform headers (`x-faas-invocation-id`,
   `x-faas-deadline-ms`) and drops client-sent `x-faas-*` values, as the
   gateway does.
3. **Reload on save.** A change under a function's root replaces that
   function's workers (and rebuilds a Go function) before the next request.
4. **Triggers.** `gregale dev trigger --local <invoke|cron> NAME` calls the
   running server with the platform headers a cron or async call carries.
   Only a request carrying the session's token, written to a 0600 state file
   in the project's `.gregale/` directory, may set them.
5. **Resources: remote by default, offline optional.** A local function
   reaches Postgres, buckets and secrets of the developer's remote `gregale
   dev` session by default; `--offline` uses local stand-ins (Docker
   Postgres and an S3-compatible store) instead. These ship as later slices.
6. **Slices.**
   - Slice 1: adapters + runner core locally, server, routing, reload,
     triggers, env from `gregale.yaml` (`env:`) and an `--env-file`.
   - Slice 2: remote session resources as the default.
   - Slice 3: `--offline` stand-ins.

## Consequences

- Local behaviour follows production automatically when the adapters or
  runner core change, because they are the same code.
- Local runs do not reproduce the microVM: no memory cap, no pause between
  requests, no snapshot. The server says so at start, and `gregale dev`
  (remote) stays the way to check those.
- Node, Python and Go must be installed locally for their functions.

## Alternatives

- **Re-implement the protocol in the CLI.** Drifts from production.
  Rejected.
- **Run the runner images in Docker.** Closer to production, but slow to
  start and requires Docker for every user. Rejected for the default path.
