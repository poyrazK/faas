# ADR-20261026145832: One command tree for the gregale CLI

Date: 2026-10-26
Status: Accepted
Related: ADR-083 (CLI manifest), [CLI DX roadmap](../cli-dx-roadmap.md), ADR-20261026110240 (agent docs, AGENTS.md and the Claude Code plugin, which quote CLI commands)

## Context

The CLI grew one top-level command per feature. An audit of the manifest
(`cmd/gregale/cli_meta.go`) on 2026-10-26 counted 120 customer top-level
commands, about 1,270 subcommands up to five levels deep, 1,313 distinct
flag names and 11 aliases. Nothing defines how a command is named.
`cliRelatedCommands` adds "See also" links between names that are easy to
confuse, and `cliHelpGroups` says "Commands keep their names; only discovery
changes". Help can explain a confusing name, but it can't make the name clear.

What goes wrong:

- **Names one letter apart.** `deploy` / `deploys` / `deployment` /
  `deployments`, `preview` / `previews`, `slo` / `slos`, `dashboard` /
  `dashboards`, `app` / `apps`, `run` / `runs`. In each pair the two names do
  different things: `deploy status` and `deploys status` read different
  objects, `previews` joins early-access features while `preview` manages
  pull-request environments.
- **Commands that duplicate each other.** `deploy abort` and `deploys cancel`;
  `deployment advance` and `canary advance`; `apps tcp` and `app tcp`; `queue
  state` and `queue status`; `edge-rules suggest`, `throttle-suggestions` and
  `routes advise`; `dlq`, `queue dead-letter`, `triggers dlq` and `events
  delivery-dead-letter`; `crons` and cron-kind `triggers`.
- **Names that say the wrong thing.** `crons fire-now` reads an earlier
  manual fire and doesn't fire anything. `deploys clear` hides a
  deployment. `queue send`, `peek` and `ack` say "wake queue" in their help
  but work on the app's own queue. `env` means both a project environment and
  environment variables.
- **One namespace, several products.** `mcp` connects agents to Gregale,
  hosts customers' MCP servers, works as a generic MCP client, and holds
  PagerDuty, maintenance and incident settings under `mcp readiness`.
- **Verbs.** Deleting is spelled `rm` 30 times, `delete` 16, `remove` 5,
  plus `unset`, `destroy` and `purge`. Reading one item is spelled `get` 34
  times, `show` 27, `info` 13 and `inspect` 6.
- **Verb chains.** `events` has 96 subcommands, 47 of them `subscription-*`.
  The longest is `events subscription-lineage-retry-control-plan-preflight`.
- **Flags.** `--profile` picks a connection before the command and a RAM size
  after it, and means five other things in other commands. `--plan` has 11
  meanings. An environment is `--scope` (49 uses), `--environment` (33),
  `--env` (3) or `--stage`. Paging uses `--cursor`, `--after` or `--offset`.
  Skipping a prompt uses `--yes`, `--force`, `--confirm` or `--quiet`.

## Decision

The goal is a dead simple CLI that people and agents can use without a
manual: a small set of nouns they can guess, the same verbs everywhere, and
the same flags everywhere. Every current command keeps working as a hidden
alias, so no script, agent or CI workflow breaks.

### 1. Rules

1. **Shape.** `gregale <noun> [<subnoun>] <verb> [<target>] [flags]`. At
   most three words come before the target.
2. **Nouns are singular** (`app`, `release`, `alert`), the way
   `gh` and `docker` name theirs. The plural is an alias of the same noun, so
   two commands can never differ by one letter.
3. **Standard verbs.** `list`, `get`, `create`, `update` and `delete` for
   records; `set`/`unset` for key-value settings; `enable`/`disable`,
   `pause`/`resume`, `cancel`, `retry`, `wait`, `watch`, `logs`, `diff`,
   `doctor`. `ls` is an alias of `list`; `show`, `info` and `inspect` of
   `get`; `add` of `create`; `rm`, `remove` and `destroy` of `delete`.
   `status` is kept for live state that changes by itself (queue depth, SLO
   budget, rollout progress); a stored record is read with `get`. A path may
   also end with a noun it lists or shows: `app instances`, `metric
   requests`, `billing invoices`.
4. **Domain verbs only when no standard verb fits**, with one meaning
   everywhere: `promote`, `rollback`, `purge`, `rotate`, `approve`,
   `reject`, `accept`, `join`, `leave`, `explain`, `replay`, `recover`,
   `resolve`, `scale`, `park`, `wake`, `restart`, `rename`, `restore`, `exec`,
   `cp`, `port-forward`, `run`, `deploy`, `publish`, `send`, `deliver`,
   `receive`, `peek`, `ack`, `apply`, `check`, `verify`, `audit`, `setup`,
   `sync`, `connect`, `disconnect`, `link`, `advance`, `simulate`, `hide`,
   `prune`, `reorder`, `serve`, `call`, `complete`, `read`, `render`.
5. **Shortcuts.** A fixed set of top-level verbs covers the daily loop:
   `init`, `dev`, `deploy`, `logs`, `status`, `open`, `rollback`, `run`,
   `invoke`, `add`, `link`, `unlink`, `login`, `logout`, `signup`, `whoami`,
   plus `help`, `version` and `completion`. Each one is a single command or
   exactly one noun command (`rollback` = `release rollback`, `run` =
   `sandbox run`). No other verb is added at the top level.
6. **No hyphenated verb chains.** `subscription-pause` becomes `subscription
   pause`. A hyphen is allowed only inside a compound noun (`data-api`,
   `rule-list`, `egress-allowlist`) and in `port-forward` and `wake-ahead`.
7. **Operator tools live under `gregale admin`**, hidden from customer help.
8. **A test enforces this** (see Implementation).

### 2. Glossary: one word, one meaning

| Word | Means | Never means |
|---|---|---|
| app | a deployed service or function | — |
| release | one build and rollout of an app (today's "deployment") | — |
| preview | a pull-request environment | early access (`feature`), a dry run (`--dry-run`) |
| environment | a project environment (production, staging) | variables (`env`) |
| env | an app's or environment's variables, all sealed | a project environment |
| feature | a Gregale feature you can see or join early | a customer feature flag (`flag`) |
| flag | a customer feature flag | — |
| run | one execution of a job, cron, workflow or automation | a sandbox (`sandbox`) |
| sandbox | a disposable code runner | — |
| invocation | one call to an app or function | — |
| plan | a subscription plan | a dry run, a saved change plan (`--plan-file`) |
| dlq | items that exhausted their retries, from any source | — |

### 3. The tree

```
gregale
Daily      init · dev · deploy · logs · status · open · rollback · run · invoke · add
           link · unlink · login · logout · signup · whoami      (+ help · version · completion)

Ship       release      list · get · logs · wait · cancel · retry · resume · diff · rollback
                        hide · prune · reorder · runtime · alias · contract
                        canary · traffic · approval · approve · reject · freeze
                        gate · schedule · mirror
           preview      create · list · get · wait · delete          (pull-request previews)
           environment  list · create · get · diff · promote · rollback · protect · history
           project · build · github · registry · test

Run        app          list · get · update · delete · restore · rename · restart · scale
                        exec · cp · port-forward · health · changes · costs · security
                        instances · park · wake · wake-ahead · network · egress-allowlist
                        egress-ports · static-egress-ip · listener · binding
           sandbox      run · list · get · cancel · artifacts       (run = sandbox run)
           invocation   list · get · wait · watch                   (invoke = call once)

Configure  env          set · unset · list · pull · push · diff · history · rollback · rotate
           domain       create · list · get · delete · setup · verify · doctor
           edge         rule · rule-list · cache · cors
           api          route · spec · consumer · tenant
           flag         get · apply · history · rollback · promote

Data       bucket · pipeline · data-api · ai · realtime   (add postgres|bucket|datadog)

Work       cron · trigger · job · worker · workflow · automation
           event        publish · send · subscription · replay · recovery
           webhook      list · create · get · update · delete · deliver · deliveries · retry
           queue · dlq

           alert        create · list · get · update · delete · channel · incident · slo
                        check · maintenance

           admin        (hidden: operator tools)
```

`gregale help` keeps about ten daily commands. `help --all` lists the 16
shortcuts and 43 nouns in the eight families above, down from 120 entries in a
flat list.

### 4. Decisions on each family

- **Ship.** `deploy` only deploys. Everything about an existing deployment is
  a `release` verb, and the release-safety controls (canary, traffic split,
  approvals, freezes, gates, scheduled releases, traffic mirror) live under
  `release` too. `preview` means pull-request environments.
- **Run.** `app` is verb first: `gregale app scale api`, not `gregale app api
  scale`. The app is the first argument after the verb, `--app`, or the
  linked app. A verb wins over an app whose slug is spelled the same, so
  an app named `list` is addressed as `gregale app get list` or `--app list`.
  `ps`, `park`, `wake`, `wake-ahead`, `wake-timeline`, `inspect`, `bindings`
  and the TCP/UDP listener commands move under `app`.
- **Variables.** `env set KEY=VALUE` (as Vercel spells it) owns every
  variable, taking over `secrets` and `env push/pull/diff/history/rollback`.
  Project environments are `environment`.
- **Time.** `cron` owns every schedule, including cron-kind triggers and
  one-off delayed tasks (`cron create --at`). `trigger` is message brokers
  only. Exclusive "operations" become a `--lock` option on `job`, `cron` and
  `trigger`.
- **Messaging.** `event` publishes, sends to one app and manages
  subscriptions and replays. `webhook` registers and delivers. `queue` is the
  app's queues. One `dlq` lists every exhausted item with `--source`.
- **Observe.** `logs`, `metric` (with request breakdowns from `analytics`),
  `debug` (with `trace` and `issues`), `dashboard` and `audit`. Alerting is
  one `alert` family: rules, channels, incidents, SLOs, uptime checks and
  maintenance windows, including the PagerDuty and maintenance settings that
  sit under `mcp readiness` today.
- **Edge and API.** `domain` holds custom domains. `edge` holds rules, rule
  lists, cache and CORS. `api` holds the API product: `route`, `spec`
  (OpenAPI), `consumer` and `tenant`. Customer feature flags are `flag`.
- **Agents.** `mcp` connects an agent to Gregale (`serve`, `config`,
  `connection`). `mcp server` holds the MCP servers a customer hosts, and
  `mcp client` the generic MCP client.
- **Account.** `billing` takes over `plan`, `usage`, `invoices` and
  `overage-cap` (`billing spend-cap`). `account` takes over `mfa`, `org`
  takes over `invitations`, `key` is API keys, and `config` takes over
  `profile`, `context` presets and `upload-cache`. `feature` lists Gregale
  features and joins or leaves early access (today `capabilities` and
  `previews`).
- **Status.** Plain `gregale status` shows what this checkout targets and how
  that app is doing. The platform status page moves to `status --platform`.
- **Advanced.** Operator tools (`admin`, `sites`, `data-repair`, `commit`,
  `entities`, `product`, `tenant-surfaces`, `postgres`, the operator
  `rollouts`, `github-webhook-secret`, `mail`) and operator recovery chains
  (`events subscription-lineage-*`, the internal invoice commands) move under
  hidden `admin`.

### 5. Flags

| Concept | Flag | Replaces |
|---|---|---|
| app | `--app` (or the first argument) | `--slug` |
| environment | `--env` | `--scope`, `--environment`, `--stage` where they name an environment |
| release | `--release` | `--deployment`, `--deployment-id`, `--deploy` |
| skip a confirmation | `--yes` | `--confirm`, `--quiet`, and `--force` where it skips a prompt |
| overwrite | `--force` | |
| show the change, change nothing | `--dry-run` | `--preview`, `--check` used as "no writes" |
| local plan / saved plan | `--plan` (boolean, deploy only) / `--plan-file PATH` | `--plan PATH` (10 meanings) |
| gate in CI | `--check` | means only "exit non-zero unless healthy or clean" |
| machine output | `--json` (global) | `--format json` |
| report layout | `--format text\|markdown\|csv` | |
| write a file | `--output`, `-o` | |
| paging | `--limit`, `--cursor`, `--all` | `--after`, `--offset`, `--page-size` |
| time window | `--since`, `--until` | `--from`, `--to`, `--start`, `--end` used for times |
| stream | `--follow`, `-f` | `--watch`, `--tail` |
| block until done | `--wait`, `--timeout` | |
| connection | `--profile`, before the command only | command-level `--profile` becomes `--size`, `--lifecycle` or `--probe-file` |

Destructive commands behave the same everywhere: `delete` asks in a
terminal, `--yes` skips the prompt, and a non-interactive run without `--yes`
fails.

## Implementation

Units release independently (docs/release-compatibility.md), and agents, CI
workflows, starters' AGENTS.md and the Claude Code plugin call today's names.
The change is additive first, and no old name is removed by this ADR.

1. **New names run today's commands.** `cmd/gregale/cli_tree.go` maps each
   path in the new tree to the command that implements it today, and `run()`
   rewrites a new path before dispatch, before capability gating and help.
   An old path is never rewritten, except that under `app` a verb in the new
   tree wins over a slug. `gregale <noun>` and `gregale <noun> --help`
   print the noun's verbs, with today's verbs in their standard spelling.
   Tests check that every target exists in the manifest, that no new path
   names one of today's commands, and that every path the table adds follows
   the rules above. Today's verbs that pass through a noun unchanged
   (`cron fire-now`) are renamed in step 2; a baseline test over them, which
   only shrinks, lands with the first of those PRs.
2. **Merges that change behavior**, one small PR each: `release get` (today
   `deploys status`, `deploys show` and `deployment summary`), `release
   cancel` (with `deploy abort`), `app health` (with `inspect`), `app
   listener --protocol`, `feature list` (with `previews list`), `dlq
   --source`, `logs` views (`saved`, `views` and `defaults`), `deploy check`
   (with `doctor`), `deploy --plan` (with `scan`), `cron create --at` (with
   `delayed-task`), `--lock` (with `operations`), `edge cache set --method`,
   alert maintenance and channels (with `mcp readiness`), and the `event` and
   `automation` subnouns.
3. **`status`** shows the linked app; `status --platform` shows the platform.
   Bare `dashboard` becomes the noun (`open dashboard` opens the browser;
   `dashboard list` already works from step 1). The old meanings print a
   one-line notice for one release.
4. **Flags** get their new spellings as aliases first; old spellings stay
   accepted.
5. **The flip.** Help, `gregale man --markdown`, the reference, docs pages,
   AGENTS.md, the Claude Code plugin, MCP tool descriptions and faas-web
   switch to the new names. Old names move to `cliAudienceCompatibility` and
   print a one-line hint on stderr in a terminal; `--json` and
   `--non-interactive` runs print nothing extra.
6. **`admin`** takes the operator tools.

Old names stay accepted for at least 12 months. Removing any of them needs
its own ADR.

## Consequences

- One rule set answers "what is this called" for every new feature, and the
  naming test keeps new commands from adding to the drift.
- Root help shows eight families instead of 120 flat entries; people and
  agents can guess a command from the noun and a standard verb.
- An app whose slug equals a verb under `app` must be addressed with `--app`
  or `app get <slug>` once the verb exists.
- The manifest carries the old names as aliases for at least a year.
- Docs, the generated reference, AGENTS.md, the Claude Code plugin skills and
  MCP tool descriptions change in step 5, not before.
