# ADR-281 · Per-integration outbound circuit breaker

- **Status:** accepted
- **Date:** 2026-09-27
- **Decision:** Add an opt-in breaker per outbound integration. Zero-valued `circuit_breaker_failure_threshold` and `circuit_breaker_open_seconds` disable it; enabled policies require both values, bounded to 1–20 consecutive transient failures and 1–300 seconds of cool-down. After cool-down, permit exactly one half-open provider probe across all gateway replicas. Count final network errors, timeouts, and HTTP 408/425/429/5xx as failures; treat ordinary 4xx as reachable-provider success, and caller cancellation or local failures before a provider outcome is available as neutral. A successful retry is one successful logical request. Keep breaker counters, open deadline, and probe lease in Postgres admission state.
- **Why:** A failing provider can consume concurrency and retry capacity across all callers. Per-integration shared state can shed calls during an outage without requiring each application to implement a wrapper, while a single half-open probe makes recovery gradual and coordinated.
- **Consequences:** Customer policy updates take effect on subsequent admissions and reset the breaker state when either breaker setting changes. Open decisions return 503 with a bounded rejection reason and `Retry-After`; because the check follows normal admission, these requests still consume admission budgets. Circuit checks run only for provider cache misses; eligible fresh cache hits remain available while the provider circuit is open. The breaker does not retry requests itself, change provider credentials, or promise a dollar-based budget.
- **Rejected alternatives:** Process-local state would let each replica send a probe and would fragment failure history. Opening on every non-2xx response would confuse provider application errors (such as authorization or validation failures) with provider availability. An unbounded cool-down would make recovery dependent on manual intervention.
