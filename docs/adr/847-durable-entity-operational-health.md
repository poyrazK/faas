# ADR-847: Bounded durable entity operational health

Status: Implemented locally; verification pending.

## Decision

Add an explicitly opt-in, read-only bucket health worker controlled by
`FAAS_DURABLE_ENTITY_HEALTH_ENABLED=1`. It requires the existing invocation
preview, app allowlist and private delimiter listing; its discovery probe does
not require DELETE or index access. Alarm, relay and maintenance enablement are
independent. Default enablement remains off.

A poll reads at most eight entity prefixes every 30 seconds, with a 20-second
page deadline and two-second per-entity read deadline. These limits live in
`pkg/api/limits.go`. Every sample verifies a manifest and its snapshot, filters
by the configured app allowlist and projects only alarm/outbox health. It does
not acquire ownership, dispatch guests, repair hints or write bucket state.
An unreadable manifest cannot be filtered safely and marks the rotation partial.

The worker accumulates scalar totals across a discovery rotation, with no
per-entity cache. Only a completed rotation with no listing or entity-read
failures publishes new backlog/exhaustion observations and a success timestamp.
Failed/partial rotations preserve previous gauges and expose discovery failure.
A retried listing page resumes its cursor; an incomplete entity-read rotation
restarts after reaching the end. Readers must check freshness and scanner health.

## Age and compatibility

New outbox messages contain optional `committed_at` metadata, generated by the
engine clock when preparing their immutable committed transition. It is a
pre-publication timestamp, not an exact bucket acknowledgement time. It is
preserved across unrelated transitions, replay, reservation, restart and recovery;
never accepted from guest intent fields. Message IDs and receiver envelopes do
not change. Encoded timestamp bytes count toward existing snapshot/outbox limits.

Existing schema-3 snapshots and messages without this optional field remain
readable. Their age is unknown; the worker publishes a separate unknown-age
message count and computes the oldest known timestamp only. No migration,
backfill or invented age is performed. Older schema-6 writers may omit optional
age metadata during rewriting; this remains an unknown-age observation rather
than execution authority. This metadata does not require a schema fence.

Alarm backlog age begins at the saved alarm deadline. Future deadlines have no
positive overdue age. Outbox age stops when the message leaves the bucket queue;
it does not measure receiver completion or transport dead-letter age. Wall-clock
skew can affect age measurements.

## Metrics and alerts

Expose per-replica `apid_durable_entity_health_*` gauges for worker enablement,
scan health, last successful rotation, observed entities, pending work, exhausted
entities, oldest known pending timestamp, and unknown-age messages. Page outcome
counters use success/partial/failed labels. Targets are fixed `alarm`/`outbox`.
No app/account/entity/message/provider identifiers enter metric labels.

These are non-atomic observations from rotating LIST/read samples, not exact
fleet inventory. Concurrent writes and provider listing movement can omit or
repeat observations; replicas may observe the same bucket. Never sum replica
values as a fleet total or use these gauges for billing, dispatch or ownership.

Recovery operations use the existing operation counter with bounded
`retry_alarm`/`retry_outbox` names. Stale recovery observations classify as
conflict. These counters cover engine attempts after API admission, not every
HTTP authorization/validation rejection.

Prometheus rules warn on failed/stale health scanning, observed exhaustion and
aged known backlog. Backlog/exhaustion rules require enabled scanning, healthy
polls and a successful rotation less than 15 minutes old. The observation-age
threshold is an initial operational threshold, not an SLO. Large buckets may
legitimately need longer rotations and require threshold/capacity review.

No tests, builds, lint, Prometheus rule execution, native acceptance or live
bucket checks were run, per user instruction. Formatting and diff review are
not qualification evidence. Work remains local with no PR or deployment.

Written cases cover exhausted work excluded by due-only scanners, allowlist
filtering, no bucket writes, unknown legacy ages, corrupt committed state,
preserved timestamps on replay, bounded metric labels, failed-rotation retention
and an API recovery → deduplicated transport handoff → cleared health backlog
flow preserving business state without guest dispatch.
