# ADR: Website sales inquiry capture and routing

Status: Accepted 2026-11-03

## Context

Salespeople need website contact/demo requests to reach the existing lead
pipeline, with clear ownership and a first follow-up. Public messages and codes
are unverified; they cannot confer account access or financial referral credit.

## Decision

Apid owns `sales_inquiries`, an intake routing singleton and opaque expiring
anti-replay receipts. Store an original message, latest repeat message, intent,
requested salesperson code, normalized email and linked lead/task. No IP or user
agent is persisted. A partial unique index deduplicates open emails; a row lock
serializes intake and manager assignment across processes. The signed one-hour
form token is purpose-bound to the existing session binding key, must be at
least two seconds old, and is consumed in the same transaction as capture.
Retries return the same generic acceptance, even with a changed body. Bounded
cleanup removes expired receipts during writes. Honey-pot submissions receive
acceptance without storage. A separate ten-request-per-minute IP budget covers
challenge and submission without consuming authentication budgets. This deters
basic bots; it does not prove a human or email ownership.

A valid active sales code routes to its eligible owner. Code-free inquiries
rotate deterministically over configured reps who are active, email-verified
and MFA-enrolled. Managers are eligible for explicit-code/manual assignments,
but are excluded from generic rotation. Reuse a unique existing eligible lead
owner before rotation. Unknown, paused, non-sales or unavailable codes,
conflicting/multiple leads and unavailable owners enter manager review. Public
responses reveal no routing or code validity. Repeat requests retain original
ownership, message and staff-maintained lead fields; the latest unverified
message is shown separately. Assignment creates a calendar-date task in the
same transaction. Repeats rearm a completed or missing initial task, retaining
one open initial follow-up. Due dates use configurable calendar days and IANA
zone (defaults one day, UTC); they are not promises of a response deadline.

Rep inquiry access derives from the current linked lead owner, so CRM
reassignment moves visibility with the lead. Managers can assign pending
requests to eligible staff, reusing that owner's lead without changing its
fields. Optimistic inquiry versions reject stale actions. Deleting a lead or
task keeps the inquiry and receipt; orphaned assignments reappear in manager
review. Closing an inquiry keeps leads and tasks and permits a later fresh
inquiry. All tables remain outside app clones. Staff reads and manager actions
are audited without message bodies. Anonymous requests are not attributed to
any salesperson as audit actor.

## Consequences

Apply the additive migration before apid. Anonymous intake has its own default-
off backend flag and matching website build flag. Disabling intake leaves the
staff inbox usable. No outbound messages are sent. Managers must monitor the
review queue, and standard database backup/access controls apply to inquiry
PII. This first release keeps the original and latest repeat message, not a
complete message history. Referral attribution still requires explicit signup
code entry; rewards remain configurable and payouts disabled.
