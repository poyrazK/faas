# duplicated numbers, because concurrent PRs each pick "the next number" and
# whichever merges second keeps it.
# scripts/ci/check_adr_number_uniqueness.sh fails on any number duplicated
# here that is NOT listed below, so a NEW collision is caught at PR time.
#
# This is a RATCHET, not an amnesty. Two rules:
#
#   1. Never add a line for a collision introduced by a PR. A new duplicate
#      is a bug the gate exists to stop. Pick the next free number instead —
#      check `ls docs/adr/` AND open PR titles, because a PR can claim a number
#      between your check and your merge. When main independently gains new
#      duplicates, refresh this frozen baseline from main so unrelated PRs do
#      not fail on collisions they did not introduce.
#   2. When a number here is renumbered so it is no longer duplicated, the
#      gate FAILS until its line is deleted. The ratchet only tightens.
#      (Same contract as pkg/state/conformance/uncovered.txt.)
#
# Retro-fixing these is deliberately out of scope for the gate: the number is
# embedded in `// adr: NNN` citation lines that check_spec_cited_tests.sh
# reads, plus metric help strings and runbooks — ADR-190 alone had 67
# references. Renumbering is its own PR, one ADR at a time.
