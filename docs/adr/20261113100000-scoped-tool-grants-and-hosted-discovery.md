# ADR-20261113100000: Scoped tool grants and hosted registry discovery

Status: Accepted
Amends: ADR-20261112210000 (private registry)
Builds on: ADR-20261104085712 (connection project limits), ADR-20261112220000 (invocation receipts)

## Context

Published versions can be discovered and invoked locally, but hosted agents
cannot read that registry. App inspection and deployment permissions do not
authorize reading every tool schema or its publisher's test evidence. Giving
an agent access to one tool must not reveal its siblings or another project.

## Decision

APID owns immutable, expiring `tool_grants` intent. The personal account's
unscoped administrator creates a grant naming an existing personal agent or
hosted MCP connection key, an exact publication version and tool name, and an
absolute expiry. The server freezes the native app and project identities.
Grant creation and revocation follow native MFA policy and emit audit events.
Agent, app, tenant, project-limited and shared-organization principals cannot
administer grants, including an MCP-login key that carries deploy-write.

Grant UUIDs are caller-retained, canonical and nonzero. Identical PUTs return
the retained record; changed intent conflicts. Revocation is irreversible for
that identity and repeated revocation preserves its timestamp. Expiry is stored
at PostgreSQL's microsecond precision. It is at most 30 days and no later than
the credential's current expiry. A rotated replacement key needs a new grant;
neither key rotation nor sliding connection renewal extends existing grants.

`allow_invocation` records an owner-approved ceiling, default false. It is not
a dispatch grant. This slice enables discovery only. Existing invocation and
publication APIs retain their local unscoped-account boundary, and hosted MCP
does not advertise invocation or source-publication tools. A later hosted
executor must separately enforce this ceiling and the invocation contract.

## Native authorization

`GET /v1/tool-registry` accepts personal agent connections carrying apps-read.
Every request reloads the key's current lifecycle and project restrictions.
Only active grants whose app and frozen project still match current native
ownership are considered. The grant can narrow current authority, never widen
it. Missing, revoked, expired, foreign and out-of-project exact tools return the
same not-found response. Search matches only permitted app/tool names, then
returns bounded, sorted version summaries containing permitted tool names.

`GET /v1/tool-registry/{version}/tools/{name}` returns a fresh canonical format-2
catalog with exactly that tool. It excludes sibling tools, resources, templates,
prompts, extensions and publisher test names. Its `catalog_contract_sha256`
describes the projected bytes; `published_catalog_contract_sha256` identifies
the full archived catalog. The runtime catalog pin remains a third identity.
Availability stays `not_checked`, evidence stays `publisher_attested`, and no
discovery response grants execution authority. Full native publication records
remain owner-only for both agent keys and MCP-login connections.

Project-limited native keys may reach exactly the search and projected-describe
GET routes; their handlers enforce the project boundary. No grant-management,
publication-journal or invocation route is added to that allowlist. All private
responses use Cache-Control no-store. No application endpoint is contacted.

## Hosted bridge and owner CLI

The existing `registry` toolset exposes `gregale_search_tools` and
`gregale_describe_tool` to personal hosted OAuth and agent-key connections.
It intersects native grants with the bridge's consented immutable app IDs.
Pagination skips excluded app pages within the bounded native publication
inventory and exposes continuation identities only for returned versions.
Every descriptor read, including the next catalog chunk, rechecks native access;
there is no authorization or catalog cache to survive revocation. Scoped MCP
responses identify `catalog_projection: single_tool` and withhold full-journal
test evidence. An organization connection still advertises neither tool.

Owners use `gregale mcp server tool-grant create|get|list|revoke`. Creation requires an
explicit retained UUID, connection key ID, exact version/tool and RFC3339
expiry. It accepts no token values, application URL, source path or arguments.
The command's optional invocation ceiling does not enable hosted execution.

## Persistence, bounds and rollout

Memory and PostgreSQL stores share the optional ToolGrantStore seam; the main
state.Store interface is unchanged. SQL is generated by sqlc. An account-row
lock serializes creation and quota checks. Foreign keys bind the account,
publication and connection key; the grant row and JSON payload bind identity,
expiry and revocation. APID is the only writer of this customer intent.

Limits in pkg/api/limits.go are 1024 retained grants per account, 64 per key,
20 owner-list entries per page and a 4 KiB intent body. Retained revoked and
expired records count toward the preview cap; revocation does not free a grant
identity for reuse. Native key deletion and account deletion cascade grants.
Managed retention is later work. No credentials or invocation inputs enter a
grant row or audit event.

Deploy the additive migration, then native API, then CLI/hosted bridge. Old
backends refuse scoped discovery rather than falling back to the full owner
journal. This change leaves product maturity at preview and deploys nothing
automatically. It does not accept or implement the proposed in-VM capability
gateway and tenant credential-custody ADRs.

## Validation

Acceptance covers memory and migrated PostgreSQL, concurrent immutable grant
creation, retained quotas, expiry and revocation, cached-key revocation,
project and connection isolation, and single-tool digest binding. Both MCP
protocols exercise hosted discovery and fresh-session reads without execution.
Native route tests cover project-limited middleware and owner-only mutation;
CLI tests cover creation, inspection and durable revocation. Portable tests do
not establish a deployed staging journey or native VM acceptance.
