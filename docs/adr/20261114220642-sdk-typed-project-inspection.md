# ADR-20261114220642: Typed project inspection in Node and Python

- **Status:** accepted
- **Date:** 2026-11-14
- **Related:** [source preparation](20261114193000-sdk-local-source-preparation.md), [deployment workflows](20261114201959-sdk-resumable-source-deployment-workflows.md)

## Context

Developers and agents can prepare, upload and observe source deployments but
must still translate a local project's manifest, workspace layout and handlers
into deployment options. Independent heuristics can select the wrong source
root or silently change intent when a process resumes.

## Decision

Expose Node `inspectProject` and Python `inspect_project` on public and preview
surfaces. Read local manifests and workspace declarations without executing
project code, Git commands, hooks or package managers. Return immutable typed
plans with resolved settings, origins, candidates, issues, input hashes and a
versioned fingerprint. Share canonical JSON and fingerprints across languages.
The fingerprint is an integrity and intent identifier, not a signature.

Follow CLI YAML precedence, build-marker priority, declared workspace selection,
function roots, conventional handler defaults and Go module contents. Support
npm/pnpm, Nx, Turbo, Go and Cargo workspace declarations. Require explicit
selection at an ambiguous repository root or among several declared functions.
Allow explicit boundary, source root, function, app, runtime, handler and Docker
overrides. Never infer a remote app from the checkout's directory name.

Bound directory traversal, regular-file reads, configuration tree size, YAML
aliases, depth and total time. Reject paths outside the project; do not traverse
symlink directories. Skip common dependency, generated and hidden directories
during workspace discovery. These SDK limits are intentionally more restrictive
than the CLI's unconstrained filesystem scan. Use safe YAML parsers (`yaml` in
Node and the already generator-used `ruamel.yaml` in Python) and TOML parsers for
Cargo declarations. Deployment TOML and function-list resource reconciliation
remain CLI work; unsupported settings block submission. Other resource sections
report deferred validation rather than claiming full schema validation. Plans
contain Docker argument names and secret IDs, never values or secret references.

Add `deployProject`/`resumeProjectDeployment` and Python equivalents as thin
adapters to existing source workflows. Bind the reviewed plan fingerprint into
the preparation policy hash without changing explicit callers' version-one
journal format or hashes. Validate inputs before and after packing. Reject
tracked build inputs excluded from archives and journals inside the inspected
project. Selected functions receive a transport-only single-function manifest
and Go functions receive a module when absent, inside the archive only. List
these generated bytes and hashes in the plan; leave the worktree unchanged.

Once prepared, resume uses the same immutable plan and archive without consulting
the current source tree. A changed plan cannot reuse the journal. Existing
receipt-only commit recovery continues to prevent repeated deployment mutations.
Old generated/static APIs, source preparation and explicit workflow calls retain
their behavior.

## Validation

Shared fixtures cover manifest precedence and invalid inputs, markers, functions,
workspace families, ambiguity, overrides, paths, build summaries and canonical
fingerprints. A stdlib Go harness compiles the actual CLI marker and workspace
matching helpers against shared fixture expectations and pins the Go toolchain.
Workflow tests inspect archive contents, worktree immutability, stale/excluded
inputs, fingerprint binding and resume after source deletion. Installed npm and
wheel consumers exercise runtime exports and strict TypeScript/mypy signatures.
Generation preservation and mirror checks include the hand-written modules,
tests and shared contracts.

## Consequences

Agents can inspect intent before authorizing an existing-app source deployment
and resume that intent across processes. Resource creation/reconciliation,
full server validation, dependency installation and local build execution remain
separate operations. Parser dependencies modestly increase SDK package size.
