# ADR-1545: Active-release worker queue canaries

- **Status:** accepted
- **Date:** 2026-10-17
- **Decision:** Admit push queue canaries for active reviewed worker deployments using exact environment release membership. Workers do not need HTTP traffic, revision-pin retention or app-level revision-pin TTL. Keep the existing revision-pin path for unmanaged deployments; other managed workload classes remain unsupported.
- **Consent:** Require `--queue-publish`, an exact deployment, and a JSON array in `GREGALE_QUEUE_CANARY_BINDINGS`. Managed workers may declare this non-secret capability in frozen reviewed variables; these override inherited deployment defaults just as in their runtime. Mutable app variables and secret aliases cannot grant capability.
- **Authority:** Freeze release identity, reviewed runtime, source generation, service-policy revision, binding release-policy revision, queue binding and trigger configuration. Validate the exact frozen push consumer contract. Recheck current authority before dispatch and whenever completion evidence is read. Publish with the release header so managed service calls retain the reviewed graph. Only persisted canary ledger membership permits this dispatch path; its queue identity and scope must also match the invocation envelope.
- **Concurrency:** Admission retains the parent app lock used by release publication. Read committed release/source authority without acquiring those owner locks in reverse order; dispatch and evidence reads recheck context. A publisher holding its release lock cannot deadlock canary admission.
- **Transport:** Recover named bound queue origin from the durable row after validating the ESM claim, lease and payload. This lets real worker deliveries pass environment isolation without trusting batch selectors. Unbound and delayed-task transport semantics remain intact.
- **Inventory:** Eligibility and publication share the snapshot resolver. Report unavailable context separately from an undeclared handler. Dry-run and strict coverage preserve these reasons and never publish without consent.
- **Bounds:** Preserve one message, one attempt, no replay generation, the original deadline, producer capacity checks, and cooperative cancellation. A claim is not handler completion; exact deployment/attempt/generation acknowledgement is still required. Source suspension, release replacement, policy changes and consumer drift revoke evidence.
- **Acceptance:** Cover portable state fences, real PostgreSQL admission/dispatch/completion, inventory eligibility and mixed HTTPS/queue strict CLI coverage. Version 3 of the managed-service native contract requires real worker handler completion, release/policy invalidation and unchanged unrelated pending work. Older service evidence cannot qualify this contract. Dedicated native KVM `test-metal` and `leakcheck` evidence remains required; compile-only fixtures do not supply it.
- **Limits:** Retain the existing rootfs and image-digest artifact requirements. Source/archive deployments without an image digest were unsupported in this slice; reviewed source-build support is added by [ADR-1546](1546-reviewed-source-binding-verification.md). Pull queues, jobs and other managed workload classes remain unsupported.
- **Prerequisite:** This changes canary admission after graph activation. Existing graph publication and release-retention configuration requirements still apply.
- **Schema:** Reuse the existing private snapshot JSON. No applied migration changes or new migration are required. Existing short-lived receipts lacking the expanded snapshot must be refreshed.
