# ADR-1207 · Verified TLS for the Postgres COMMIT-loss fixture

- **Status:** accepted
- **Date:** 2026-10-12
- **Decision:** Extend ADR-1206's opt-in loopback wire fixture with PostgreSQL SSLRequest negotiation and TLS termination. Require an explicit proxy certificate/key, upstream trust roots and server name. Verify the upstream certificate and hostname with TLS 1.2 or later; bound each negotiation with a two-second absolute deadline. The normal PostgreSQL client independently verifies the proxy identity. Forward application frames only after both handshakes succeed; never downgrade.
- **Why:** An encrypted dependency can commit successfully while its caller loses the acknowledgement. Plaintext-only protocol evidence does not exercise verified TLS negotiation, rejection or cleanup.
- **Consequences:** The owned Postgres 16 gate generates a fresh disposable loopback identity using OpenSSL, enables server TLS, and gives the Node subprocess additional CA trust without changing serving defaults. Provider and caller COMMIT-loss/replay cases run over TLS; independent SQL witnesses prove the confirmed operation and `pg_stat_ssl` proves encrypted recovery sessions. Trust/hostname failures on either leg, plaintext attempts and server TLS refusal forward no SQL and consume no armed fault. Shutdown joins incomplete negotiations and all socket wrappers. Evidence counts verified upstream sessions and TLS failures without retaining authentication/SQL payloads. Host private material and container copies are ephemeral and cleaned on failures, including uncertain container startup. The existing thirteen-case native restart gate remains unchanged: remote routing, native TLS fault qualification and mutual TLS need separate evidence.
- **Rejected alternatives:** Disabling certificate verification invalidates the deployment contract. A transparent encrypted relay cannot selectively identify a successful COMMIT acknowledgement. Reusing a checked-in private key would make the trust fixture persistent. Silently accepting plaintext after failed SSLRequest negotiation would hide a broken TLS dependency.
