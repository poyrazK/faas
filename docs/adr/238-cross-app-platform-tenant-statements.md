# ADR-238: Cross-app platform tenant usage statements

ADR-239 extends these statements with tenant-surface minute lines. The consumer-only line shape below describes the original rollout.

- **Status:** accepted
- **Date:** 2026-09-24
- **Decision:** Snapshot tenant-attributed minute usage across apps into one immutable, revisioned, single-currency statement per customer and period. Finalized statements can be handed off once to an external billing system; late usage creates an additive adjustment revision.
- **Why:** App-local statements cannot represent a platform customer spanning apps, and today's account-level tenant usage endpoint is raw, unpriced data. A billing handoff must avoid both retroactive tenant assignment and double claims of the same consumer window.
- **Consequences:** A new account-scoped API and Go client expose create/list/get/finalize/handoff. Minute lines retain the app, consumer, rate-card version, currency, units, and amount. The existing app rate cards remain the pricing source; this does not collect payment or perform FX conversion. Unpriced or mixed-currency usage cannot become a finalized cross-app statement. We serialize app and tenant handoffs under an account row lock and reject overlapping consumer windows claimed through the other path; adjustments for the same tenant and exact period are allowed. An external invoice ID is unique across both handoff paths within an account. A 20,000-line cap bounds one snapshot; larger customers must use smaller periods. The gateway usage outbox still has the pre-fsync crash limitation described in ADR-234, so customers should reconcile late arrivals before invoice close.
- **Rejected alternatives:** Sum app-local statements (would import pre-link or otherwise unassigned traffic); infer historical ownership from the current consumer link (rewrites financial facts); mutate a finalized snapshot on late arrival (breaks auditability); auto-convert currencies (requires a foreign-exchange policy and source Gregale does not have); bill directly through a payment provider (would change the merchant-of-record boundary).

An initial statement is revision 1. Repeated creation while its draft is open returns that same snapshot if the priced usage is unchanged. If rates or usage change, the old draft is marked `superseded` and a new immutable revision snapshots all still-unfinalized units; this avoids trapping a customer behind an unpriced draft after a rate card is added. Once a revision is finalized, create replays the latest revision when no new tenant-attributed units exist, or snapshots only the positive difference between current minute aggregates and all finalized revision lines. A drop below previous coverage fails closed; it is not a negative credit note. The separate invoice handoff receipts preserve immutable external references, not a payment status. Overlap exclusion is conservative at the consumer/window level: an app-local statement covering both pre-link and tenant-attributed traffic still cannot be handed off alongside the tenant statement for that same window. Finer usage-level partitioning is future work.
