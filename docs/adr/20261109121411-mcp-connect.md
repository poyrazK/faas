# ADR-20261109121411: `gregale mcp connect` sets up an agent's MCP client

Date: 2026-11-09
Status: Accepted
Related: ADR-20261026195952 (hosted MCP server), ADR-20261029085359 (agent
keys), ADR-20261026152009 (toolsets), ADR-20261104140058 (agent approvals)

## Context

Connecting an agent to Gregale means copying a client-specific snippet:
`claude mcp add …` for Claude Code, a TOML table plus `codex mcp login` for
Codex, and extra headers for agent keys or toolsets. Nothing checks the result.
A user whose agent "does not see Gregale" has no tool to find out why.

## Decision

### 1. One command

`gregale mcp connect` writes the Gregale MCP server into the user's agent
clients and checks the connection.

```
gregale mcp connect [--client claude-code|codex]... [--project]
                    [--toolsets core,operate] [--headless] [--force] [--dry-run]
```

- With no `--client`, it detects the installed clients (Claude Code: `claude`
  on PATH; Codex: `codex` on PATH or `~/.codex`) and, in a terminal, asks
  before writing each one. `--yes`/`--non-interactive` connects every detected
  client without asking. Nothing detected is an error that names the clients
  it knows.
- The server is the hosted one: the profile's API base plus `/mcp`. There is
  no local (`gregale mcp serve`) mode in this command.
- The config is user-wide by default, so the agent sees Gregale in every
  project. `--project` writes the project's config instead: Claude Code's
  `.mcp.json`. Codex has no project config, so `--project` refuses Codex.
- An existing `gregale` entry with the same URL and options is reported as
  already connected. A different one is left alone unless `--force` replaces
  it. `--dry-run` prints what would be written.

### 2. Per client

- **Claude Code:** runs `claude mcp add --transport http --scope user|project
  gregale <url>`, with `--header` for toolsets and headless. With `--force` it
  removes the old entry first. Claude Code owns its config files, so Gregale
  never edits them directly.
- **Codex:** edits `~/.codex/config.toml`. It adds or, with `--force`,
  replaces only the `[mcp_servers.gregale]` table: `url`, `http_headers` for
  toolsets, and `bearer_token_env_var` when headless. Other tables and
  comments are kept byte for byte. Then it runs `codex mcp login gregale` in a
  terminal, unless headless.

### 3. Sign-in or agent key

By default the agent signs in through the browser the first time it connects
(OAuth, ADR-20261026195952). No secret is written anywhere.

`--headless` is for agents with no person at a browser. It mints an agent key
(`agent,deploy:write`, every approval category, label `mcp-<client>-<host>`).
The config refers to the key only through the `GREGALE_AGENT_KEY` environment
variable: Claude Code's header `${GREGALE_AGENT_KEY}`, Codex's
`bearer_token_env_var`. The key is printed once, with the line to export it,
and never written to disk by Gregale.

### 4. Check

After writing, the command checks what it can without the agent:

- the hosted endpoint answers (an unauthenticated MCP request gets 401 with
  OAuth metadata, not a network error or 404);
- the client lists the entry (`claude mcp get gregale`; Codex: the table
  reads back);
- headless: the new key initializes an MCP session and lists tools, and the
  command reports the tool count.

It ends with the next step: open the agent and sign in when the browser opens.
With `--json` it prints one result object per client.

### 5. `--check` (amended 2026-11-10)

`gregale mcp connect --check` changes nothing. It explains why an agent does
not see Gregale, one line per check, each problem with the command that
fixes it:

- **endpoint:** the hosted server answers.
- **claude-code, codex:** the client is installed and its `gregale` entry
  points at this profile's server. Signs in through the browser, or reads
  `$GREGALE_AGENT_KEY`. A client without an entry is a warning, because the
  user may use another one.
- **project:** this directory's `.mcp.json`, when there is one.
- **setup:** fails when no client and no project config is set up.
- **agent_key:** when a config reads `$GREGALE_AGENT_KEY`, the variable is
  set and opens an MCP session.
- **connections:** the account's connected agents, warning on none and on
  any ending within 72 hours.
- **approvals:** requests waiting for a person, with the first review link.
  An agent waiting on one is blocked.

It exits 1 when a check fails, and `--json` prints every check.
`gregale mcp doctor` already diagnoses MCP servers customers host on
Gregale, so this check is a mode of the command it verifies instead.

### 6. `gregale init` writes `.mcp.json` (amended 2026-11-10)

`gregale init` adds a `.mcp.json` naming the hosted server
(`{"mcpServers":{"gregale":{"type":"http","url":…}}}`). Claude Code and
Cursor offer it to anyone who opens the project. It holds no secret; the
agent signs in through the browser. A template that ships its own
`.mcp.json` keeps it, and `--no-mcp` leaves it out. Only `init` writes it:
the template archives that `deploy --template` uploads do not include it.

### 7. More clients (amended 2026-11-10)

`--client` also takes `cursor`, `vscode`, `windsurf` and `claude-desktop`,
and detection finds them by binary (`cursor`, `code`, `windsurf`) or by
settings directory.

| Client | User config | Project config | Entry |
|---|---|---|---|
| Cursor | `~/.cursor/mcp.json` | `.cursor/mcp.json` | `mcpServers.gregale.url` |
| VS Code | `Code/User/mcp.json` in the OS settings dir | `.vscode/mcp.json` | `servers.gregale` with `type: http`, `url` |
| Windsurf | `~/.codeium/windsurf/mcp_config.json` | none | `mcpServers.gregale.serverUrl` |

- **Editing:** Gregale edits only the `gregale` entry. Other keys keep
  their values and order.
- **Comments:** a config with comments or trailing commas is refused and
  never rewritten. The refusal prints the entry to add by hand.
- **Headless:** the configs read the key as `${env:GREGALE_AGENT_KEY}`.
- **Claude Desktop:** it adds remote MCP servers only under Settings →
  Connectors, so `connect` prints those steps and `--check` skips it.
  Connectors sign in through the browser, so an agent key cannot be used
  there.
- **`--check`** reads each JSON client's user config, then its project
  config.

### 8. An agent in GitHub Actions: `--ci` (amended 2026-11-10)

`gregale mcp connect --ci [--repo OWNER/NAME]` sets up an agent that runs in
GitHub Actions:

1. **Checks gh:** it needs `gh`, signed in, and the repository (default:
   the current clone's). It reads the repository's secret names, so a
   missing admin right fails before anything is minted.
2. **Mints an agent key:** `agent,deploy:write`, needing approval for every
   kind of risky action (delete, production, credentials, billing),
   labelled `ci-<owner>-<name>`. `--scopes` and `--approvals` change it.
3. **Stores the key** as the repository secret `GREGALE_AGENT_KEY` with
   `gh secret set`, passed on stdin. The key is never printed, written to
   disk or passed as an argument. An existing secret is replaced only with
   `--force`, which mints a new key; the old one stays valid until revoked.
4. **Writes `.github/workflows/gregale-agent.yml`** unless it exists
   (`--force` replaces it). The workflow runs on demand with a task; checks
   that the key opens an MCP session; then runs Claude Code headless, with
   Gregale's server from an MCP config that reads `${GREGALE_AGENT_KEY}`.
   It needs an `ANTHROPIC_API_KEY` secret, and the agent can be swapped.
   Requests needing approval wait for a person in Gregale.

`--dry-run` prints the workflow and changes nothing. Decisions: a mode of
`mcp connect`, not a new noun; deploy with every approval kind by default;
write the workflow file for the user to commit; a repository secret, not an
environment secret.

## Consequences

- One command replaces client-specific snippets for the two most common CLI
  agents; docs keep the snippets for other clients.
- Codex's config is edited by Gregale, so the editor must keep unrelated
  content intact; tests pin that.
- `gregale mcp doctor` (connection diagnosis) and more clients (Cursor,
  VS Code, Claude Desktop, Windsurf) can build on the same detection and
  check later.
