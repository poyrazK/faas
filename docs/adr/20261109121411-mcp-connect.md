# ADR-20261109121411: `gregale mcp connect` sets up an agent's MCP client

Date: 2026-11-09
Status: Accepted
Related: ADR-20261026195952 (hosted MCP server), ADR-20261029085359 (agent
keys), ADR-20261026152009 (toolsets), ADR-20261104140058 (agent approvals)

## Context

Connecting an agent to Gregale means copying a client-specific snippet:
`claude mcp add …` for Claude Code, a TOML table plus `codex mcp login` for
Codex, and extra headers for agent keys or toolsets. Nothing checks the result.
A user whose agent "does not see Gregale" has no tool to find out why.

## Decision

### 1. One command

`gregale mcp connect` writes the Gregale MCP server into the user's agent
clients and checks the connection.

```
gregale mcp connect [--client claude-code|codex]... [--project]
                    [--toolsets core,operate] [--headless] [--force] [--dry-run]
```

- With no `--client`, it detects the installed clients (Claude Code: `claude`
  on PATH; Codex: `codex` on PATH or `~/.codex`) and, in a terminal, asks
  before writing each one. `--yes`/`--non-interactive` connects every detected
  client without asking. Nothing detected is an error that names the clients
  it knows.
- The server is the hosted one: the profile's API base plus `/mcp`. There is
  no local (`gregale mcp serve`) mode in this command.
- The config is user-wide by default, so the agent sees Gregale in every
  project. `--project` writes the project's config instead: Claude Code's
  `.mcp.json`. Codex has no project config, so `--project` refuses Codex.
- An existing `gregale` entry with the same URL and options is reported as
  already connected. A different one is left alone unless `--force` replaces
  it. `--dry-run` prints what would be written.

### 2. Per client

- **Claude Code:** runs `claude mcp add --transport http --scope user|project
  gregale <url>`, with `--header` for toolsets and headless. With `--force` it
  removes the old entry first. Claude Code owns its config files, so Gregale
  never edits them directly.
- **Codex:** edits `~/.codex/config.toml`. It adds or, with `--force`,
  replaces only the `[mcp_servers.gregale]` table: `url`, `http_headers` for
  toolsets, and `bearer_token_env_var` when headless. Other tables and
  comments are kept byte for byte. Then it runs `codex mcp login gregale` in a
  terminal, unless headless.

### 3. Sign-in or agent key

By default the agent signs in through the browser the first time it connects
(OAuth, ADR-20261026195952). No secret is written anywhere.

`--headless` is for agents with no person at a browser. It mints an agent key
(`agent,deploy:write`, every approval category, label `mcp-<client>-<host>`).
The config refers to the key only through the `GREGALE_AGENT_KEY` environment
variable: Claude Code's header `${GREGALE_AGENT_KEY}`, Codex's
`bearer_token_env_var`. The key is printed once, with the line to export it,
and never written to disk by Gregale.

### 4. Check

After writing, the command checks what it can without the agent:

- the hosted endpoint answers (an unauthenticated MCP request gets 401 with
  OAuth metadata, not a network error or 404);
- the client lists the entry (`claude mcp get gregale`; Codex: the table
  reads back);
- headless: the new key initializes an MCP session and lists tools, and the
  command reports the tool count.

It ends with the next step: open the agent and sign in when the browser opens.
With `--json` it prints one result object per client.

## Consequences

- One command replaces client-specific snippets for the two most common CLI
  agents; docs keep the snippets for other clients.
- Codex's config is edited by Gregale, so the editor must keep unrelated
  content intact; tests pin that.
- `gregale mcp doctor` (connection diagnosis) and more clients (Cursor,
  VS Code, Claude Desktop, Windsurf) can build on the same detection and
  check later.
