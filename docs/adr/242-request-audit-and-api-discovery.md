# ADR-242: Opt-in request audit and observed API inventory

- **Status:** accepted for initial implementation
- **Date:** 2026-09-25
- **Decision:** Use declared OpenAPI or explicit route templates where available; otherwise collapse numeric, UUID and long-hex path segments to `{id}` before adding a route to the existing per-app metrics inventory. When `FAAS_REQUEST_AUDIT_ENABLED=true`, attach one exact completed-request observation to the gateway's fsynced, idempotent consumer-usage outbox event. `apid` commits the audit row and financial usage increment in one transaction and acknowledges the audit evidence explicitly. An audit-enabled gateway will not discard an event after an older receiver ignores the new field.
- **Read surfaces:** `GET /v1/apps/{slug}/audit/requests` returns the newest matching exact records for a bounded time window; `GET /v1/apps/{slug}/audit/routes` returns up to 500 persisted route candidates. Both require account-scoped read authorization and MFA for sessions. The existing `/routes` remains a live, 50-route Prometheus snapshot.
- **Data:** Event ID, account, app, verified consumer and platform-tenant IDs where available, method, route candidate, status, latency, trace and request IDs, deployment ID and commit SHA, trusted source IP when available, and event time. No query string, headers, body, or unverified app-user identity is collected. Source IP and unknown literal path segments are personal-data risks; operators must review collection before enabling audit. Records older than 30 days are removed by a bounded hourly `meterd` sweep, independently of financial usage retention. Account deletion cascades to audit rows.
- **Limits:** This is a gateway request activity trail, not a universal business audit log. Gregale cannot infer the application's authenticated user or business action, and direct guest outbound calls or internal service calls require trace context and app/runtime instrumentation. A gateway crash between serving a response and the outbox fsync can omit that completed request (ADR-234). This initial table is not partitioned or suitable for unlimited fleet traffic; the feature is off by default pending capacity work. The list API is bounded to 500 records and does not yet provide a complete cursor-based export. No WORM/cryptographic tamper evidence is claimed.
- **Rejected alternatives:** Treating collapsed `request_telemetry` or sampled traces as exact audit events (lossy); putting request paths in the financial aggregate columns (privacy and billing coupling); acknowledging optional audit without a receipt bit (silent loss during rolling upgrade); asserting an app-user ID from an untrusted header (spoofable).

Deployment order is migration → `apid` → `meterd` → gateway. Enable `FAAS_REQUEST_AUDIT_ENABLED=true` only after the new receiver is serving all gateway targets and the path-privacy review is complete. The outbox will hold and retry audit-carrying events when the receiver does not acknowledge them; readiness already drains a gateway when the journal nears capacity.
