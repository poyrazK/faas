# ADR-316 · Source-ref branch freshness before promotion

- **Status:** accepted
- **Date:** 2026-09-27
- **Related:** ADR-092 (headless source-ref deploy), ADR-311 (GitHub push freshness and promotion fence), ADR-315 (Actions-owned mapped environment deployments)
- **Decision:** When a source-ref request names a GitHub branch, apid records the branch and installation identity alongside the resolved commit SHA. Imaged asks githubd for that branch's current head immediately before promoting the deployment. A deleted or advanced branch fails with `source_ref_stale`; a lookup failure or missing verifier fails closed with `source_ref_unavailable`. Tags and commit SHAs remain pinned to their resolved commit and do not receive mutable-branch metadata.
- **Why:** Source-ref imports previously kept only `github://repo@commit-sha`. The original branch was lost after fetching, so a slow build could become live even after that branch moved. The existing accepted-revision fence only catches a newer Gregale deployment intent; it cannot detect a branch update that has not itself queued a deployment.
- **Consequences:** The deployment row preserves branch and installation identity, and retries carry those immutable inputs forward. githubd validates the account/install pairing before resolving the branch. Split-box imaged reaches githubd through the private `githubd.faas:50053` mTLS listener; the manifest, firewall, and per-box PKI setup provision that route. The recheck runs after build/readiness validation and immediately before the live-pointer transaction, so stale code is never intentionally promoted and the previous live revision remains available. The remote branch read and database promotion cannot be atomic; an upstream push in the small interval between them may still race the cutover.
- **Rejected alternatives:** Checking only when apid accepts the request leaves the full build window unprotected. Treating every non-SHA ref as a branch incorrectly changes tag behavior. Using only the latest deployment revision misses upstream branch movement when no second deployment has been queued.
