# ADR-264 · Verified webhook bindings for workflow callbacks

- **Status:** proposed
- **Date:** 2026-09-25
- **Decision:** Let an account owner bind one `wait_for_callback` step to one Stripe event type and object ID on an existing app-owned inbound webhook endpoint. After normal endpoint-token lookup, bounded-body read, and Stripe signature verification, ingress looks for an exact binding. A match completes the callback directly in the workflow ledger instead of enqueueing an app invocation; an unmatched event keeps the existing inbound-webhook behavior. The binding is unique both per callback and per endpoint/type/object tuple.
- **Why:** The authenticated callback API still requires an application relay. An app-scaled-to-zero should be able to wait for a known Stripe object event without running a webhook handler merely to forward the event.
- **Consequences:** Management requires the run owner's deploy-write scope and an endpoint belonging to the same app/account. The public endpoint URL and provider signing secret retain ADR-212's lifecycle; no new bearer callback URL or secret is created. Provider retries with the same signed payload return a duplicate receipt. If the callback is already terminal or expired, a verified matching event is acknowledged as ignored so the provider does not retry an impossible completion. A different payload for an already-completed callback is likewise ignored at public ingress, while the authenticated callback API continues to report a conflict. Binding rows cascade away with their run or endpoint. The endpoint must be bound before the provider event arrives; an earlier event follows its ordinary app-delivery path.
- **Rejected alternatives:** An arbitrary unsigned public callback URL would make the URL the sole credential. A per-run Stripe webhook endpoint would require dynamic provider registration and duplicate ADR-212's secret storage. Matching only on event type could complete the wrong run. Completing the callback after an app invocation would still wake an application just to relay the event.

This is a closed-set Stripe adapter, not a generic `waitForWebhook()` that understands every provider. Other providers need explicit signature and correlation adapters. It extends ADR-212 and ADR-263; it does not add replayed code-as-workflow execution.
