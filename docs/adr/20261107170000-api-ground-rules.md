# ADR-20261107170000: API ground rules

Date: 2026-11-07
Status: Accepted
Related: ADR-1306 (denied consumer requests are not billed), ADR-1448 (rollback
release guard), ADR-20261022204036 (idempotency fingerprints), #6726 and #6735
(ChronoLake report 2 fixes)

## Context

A design review of the ChronoLake field report grouped several findings as
breaks of unwritten API rules rather than one-off bugs. Checking each against
the code on 2026-11-07:

| Finding | Rule it breaks | State |
|---|---|---|
| 12: `bucket versioning status` on a never-versioned bucket wrote a revision and a fence | reads have no side effects | fixed in #6735 |
| 33: disabled previews answered a retryable 503 | errors are classified honestly | fixed in #6735 (403) |
| 3: the idempotency cache replayed refusals | only completed operations are replayed | fixed earlier (#6682/#6683); `idempotencyReplayable` skips 401/402/403/404/429/501/503 and state-dependent 409/422 codes |
| 23: rollback guard | the server enforces safety checks | the guard already runs on the server (ADR-1448); the finding was a CLI receipt bug, fixed in #6726 |
| 32: refused requests billed as tenant usage | a response the app never answered is not billed | fixed here |
| `gregale invoke` skips edge rules | policy applies on every public path; exceptions are stated | by design; documented here |

Finding 32 in detail: the gateway billed one unit for every request with a
consumer or platform-tenant attribution unless the response was a 5xx the
guest never started (`platformFailureUnbillable`) or the refusal path set
`suppressFinancialUsage` (consumer-plan admission and tenant budget only). A
gateway-authored 401 (gateway-enforced auth on a verified tenant surface),
403 (edge rule) or 429 (route throttle) issued after attribution was billed,
although ADR-1306 already states that a denied request is not billed.

## Decision

Every new or changed endpoint follows these rules. Reviews cite them by
number.

1. **Reads have no side effects.** `GET`, `HEAD` and CLI verbs named
   `status`, `show`, `list`, `get`, `describe` or `explain` never write
   customer state, take fences, bump revisions or start work. Recording
   telemetry and audit of the read is allowed.
2. **The server enforces safety checks.** A guard that protects data or
   traffic (migrations, rollback compatibility, release acknowledgements,
   deletion protection) is enforced by the server. The CLI may check early
   for a better message, but a raw API call must hit the same guard.
3. **Errors are classified honestly.** 5xx means the platform failed and a
   retry may succeed unchanged. A feature switched off by the operator or the
   plan is a non-retryable 4xx with a stable code (403, or 501 for a
   not-yet-enabled operator gate), never 503. 429 and 503 carry
   `Retry-After` when the server knows it.
4. **Idempotent replay returns only the outcome of an operation that ran,**
   or a refusal that the same request would always get (malformed input).
   Refusals that depend on account state, time or policy are not stored
   (`idempotencyReplayable`, `idempotencyResponseReplayable`).
5. **A response the customer's application never answered is not billed.**
   The gateway's billing rule is `usageUnbillable`: no first byte from the
   guest and an error status means zero billable units, whether the gateway
   failed (5xx) or refused (4xx). A status the guest returned is billed. The
   availability SLO still counts only gateway 5xx (`platformErrorForSLO`).
6. **Policy applies on every public path, and every non-public path is a
   documented exception.** Edge rules apply to requests at public hosts. The
   service network and work the platform delivers on the account's behalf
   (`gregale invoke` and other invocations, queue messages, delayed tasks,
   crons, exclusive operations) skip them by design, because the account's
   credentials and scopes authorize that work when it is created.
   `docs/edge-rules.md` lists both.

## Consequences

- Requests the gateway refuses with 4xx after identifying a consumer or
  tenant stop producing billable units. Request and error counts are
  unchanged, so dashboards still show the refusals. Consumer and tenant
  statements for traffic with many refusals go down; nothing was billed for
  such refusals by the consumer-plan and tenant-budget paths before, so
  statements become consistent across refusal kinds.
- The debugger fallback ledger, which bills every row it writes, no longer
  receives these refusals either.
- Rules 1–4 and 6 add no code in this change. A route-level contract test
  that enforces rules 1 and 3 across the API is follow-up work.

## Validation

`TestHandlerObserveDoesNotBillPlatformFailures` gains gateway-authored 401,
403 and 429 cases (zero billable units, one error) and a guest-authored 401
(still billed).
