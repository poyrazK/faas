# ADR: Discover existing SDK work through authorized inbox reads

Status: Accepted (SDK preview)

## Context

Pipeline tools and outbound actions retain enough evidence to resume safely, but
the caller needs its original IDs. A dashboard or fresh agent session needs to
find its pending review, unresolved start, or external outcome.

## Decision

Compose bounded pointer reads over the existing PostgreSQL receipts. Scope the
scan to a verified owner and app, and bind pipeline identities to the subject,
definition, and contract. Recheck current authorization and status through each
existing adapter. Return minimized references and a suggested next operation.
Business labels are resolved by application code from existing owned records.

Reuse typed query contracts, OAuth toolkit registration, deadlines and signed
continuation. A sparse page can carry a continuation even when all scanned work
was filtered or denied. The deterministic scan position hashes the receipt
identity again, keeping discarded receipt identifiers out of the cursor.
Add application-owned expression indexes for the scoped keyset queries.

No separate workflow ledger, platform endpoint, or mutation operation is added.
Existing receipts own retention and identity. Reading the inbox does not
dispatch work or reconcile providers. Follow-up operations retain their current
access, human approval, and duplicate prevention rules.

## Evidence

Shared SDK tests cover bounded sparse paging, precision across languages,
selector and principal fences, and deadlines and cancellation. The authenticated
CSV journey discovers a pending cleanup and uncertain refund after reconnect
and verifies that another user and revoked access cannot recover those IDs.
