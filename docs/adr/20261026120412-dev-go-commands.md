# ADR-20261026120412: Developer environments can build one command of a Go module

- **Status:** accepted
- **Date:** 2026-10-26
- **Amends:** ADR-20261025134512 (each command of a multi-command Go module is a service), which left these services out of `gregale dev --all`
- **Decision:** A developer environment can build one `cmd/<name>` main package of the Go module at its source root, as a project service of that module does. `gregale dev --all` runs each such command as its own developer loop.
  - **API.** `PUT /v1/dev/sessions/{project}` takes an optional `go_command`. apid validates it (a `cmd/` directory name; not for a function), stores it as the developer app's `build_go_command`, and echoes it in the response. A request without it clears it, as `watch` does. builderd already passes the app's Go command to the builder guest and refuses an artifact the guest did not acknowledge (ADR-20261025134512).
  - **CLI.** `gregale dev --go-command NAME` selects the command. The CLI first checks that `cmd/NAME` holds a main package. If the response does not echo the command, it stops before the first sync: an API that ignores the field would build the module's default command under this command's name.
  - **`dev --all`.** Discovery includes the scanner's Go command services (root `.`, with a command) and starts each with `--path <module root> --name <service> --go-command <name>`. The `gregale start` picker leaves them out, since it launches a directory and cannot choose a command.
- **Why:** With one service per command in production, a developer of such a repository could not run the commands in development. `gregale dev` built Railpack's default command (the first under `cmd/`), and `dev --all` skipped the module.
- **Consequences:**
  - Each command gets its own developer environment, lease and developer-environment slot, like any `dev --all` app.
  - Go has no watch-mode development server, so these environments use production-shaped developer builds.
  - Rolling upgrades: the request and response fields are `omitempty`. A new CLI against an older API stops with a clear message instead of syncing. An older CLI never sends the field, so its environments keep the default build.
- **Rejected alternatives:**
  - **Infer the command from the developer project name.** The name is sanitized and can differ from the directory, and nothing would tell an older API's wrong build apart.
  - **A per-environment `gregale.yaml` key.** The selection belongs to the developer loop, not to the shared source.
