# ADR-20261031090000: PR previews keep the route contract and stop when previews are turned off

- **Status:** accepted
- **Date:** 2026-10-31
- **Amends:** ADR-095 (PR preview environments), ADR-20261026090000 (environment allowance and gate sync)
- **Decision:** A fifth code review of PR previews found these gaps; this ADR fixes them.
  1. **A preview keeps its production app's declared-route contract.** An app can answer only the routes its imported OpenAPI document declares (`only_declared_routes`, `declared_routes`). Previews copied the access and egress gates but not this contract, and the quota insert that creates API previews dropped both columns, so a preview served every path on its public host, including the ones production hides. Webhook and API previews now copy the contract when created, every new head refreshes it, and `apps_sync_preview_access_gates` copies a production change to the live previews, as it does for the other gates.
  2. **A preview is held to its production app's OpenAPI document.** The gateway loads the route contract's document by app ID, and a preview has no imported document of its own, so a preview with the contract on would refuse every request with 503 `declared_route_policy_unavailable`. The gateway now reads a preview's own document if it has one, and otherwise its production app's (the live app its `preview_of_slug` names in the same account). The matcher cache is keyed by the preview, so a new production document reaches previews within the cache TTL (5 minutes).
  3. **Turning previews off tears down open previews.** With `preview_enabled=false` on the project's policy, or the `pr-previews` capability off for the account, githubd ignored the pull requests' events while their open previews served the last built commit to the end of their lease. Setting `preview_enabled=false` through the policy API now retires the project's open PR previews (stale, lease ended, so the janitor tears them down). The next event on an open pull request whose previews are off does the same for that PR, which covers a capability turned off for the account; a pull request whose preview was still open gets a neutral `gregale-preview` check saying previews are off. Other pull requests, forks included, hear nothing, as before.
- **Why:** A preview runs unreviewed code on a guessable host; it must not expose routes production hides, must not be broken by the gate that hides them, and must not keep running after the owner turned previews off.
- **Consequences:**
  - One migration redefines `sync_preview_access_gates()` and its trigger to include the two route columns and backfills open previews from their production apps in batches. It touches only rows and a trigger, so an older apid keeps working. A preview that an older githubd or apid creates after the backfill lacks the contract until its production app's contract next changes or the new release handles the PR's next head; the deploy order (data, then control plane) keeps that window short.
  - A preview of an app whose contract is on now answers undeclared paths the way production does. A PR that adds a route needs it in the production app's imported document, or the contract turned off, before its preview serves that route.
  - `PATCH .../github/deployment-policy` with `preview_enabled:false` can fail with a retryable 503 if the previews could not be retired; the policy is already saved, and the retry is idempotent.
- **Rejected alternatives:**
  - **Import the PR head's OpenAPI document for the preview.** The contract is the production app's security boundary; letting the PR's code widen it defeats the gate on a public host.
  - **Copy the production document into an `app_openapi_docs` row per preview.** It would go stale when production imports a new document and needs its own sync; reading the parent's row keeps one source of truth.
  - **Leave open previews to their lease after previews are turned off.** A lease can last 30 days; turning previews off is how an owner stops PR code from serving.
