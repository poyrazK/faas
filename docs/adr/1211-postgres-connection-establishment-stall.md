# ADR-1211 · Bounded PostgreSQL SSLRequest connection establishment stalls

- **Status:** accepted
- **Date:** 2026-10-12
- **Decision:** Add opt-in persistent `stallConnections({phase: "ssl_request", durationMS})` control to the loopback verified-TLS proxy. Accept and validate the client SSLRequest, then withhold S before opening upstream. Each attempt is held for an integer 1–5000 ms bound; expiry closes it, disconnect/shutdown cancels it, and clearing releases live attempts into normal verified TLS. Suspend the ordinary negotiation deadline only during an explicitly selected hold, then apply a fresh two-second TLS handshake deadline after release. Malformed/incomplete requests retain their normal deadline and never count as positive stall evidence.
- **Why:** Transfer failures on established connections do not exercise applications whose dependency accepts TCP but never proceeds to TLS readiness. Pool waiters and caller-selected retries can otherwise become stuck or amplify connection attempts.
- **Consequences:** Evidence counts accepted TCP/SSLRequest attempts, pending negotiations and active hold timers, recording phase/leg, configured/monotonic duration and release/expiry/cancellation without endpoints, authentication bytes, credentials or SQL. Bound control activations and fired hold records to 100 each; excess held attempts fail closed. Existing 16-connection and frame bounds remain. Real PostgreSQL tests require bounded explicit retries, failed queued pool acquisitions, successful verified release/recovery, expiry and joined shutdown. Failed attempts provide no usable client or authenticated backend session; recovered pools have one encrypted idle client and no waiters. Final cleanup leaves no pool clients, sockets, negotiations, timers or backend sessions. No automatic write retries or serving TLS-policy changes are introduced. Authentication-phase stalls, upstream establishment faults and native/deployed qualification remain separate work.
- **Rejected alternatives:** Dropping TCP immediately does not model a dependency that accepts but never becomes ready. Treating arbitrary bytes as SSLRequest would manufacture positive fault evidence and bypass protocol validation. Disabling TLS verification on recovery would obscure a broken dependency trust contract. Releasing a stall by silently selecting plaintext or retrying indefinitely would change application semantics and undermine bounded recovery.
