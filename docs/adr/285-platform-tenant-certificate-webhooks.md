# ADR-285 · Tenant-scoped surface certificate lifecycle webhooks

- **Status:** accepted
- **Date:** 2026-09-27
- **Decision:** Add `platform_tenant.surface.certificate.changed` to platform-tenant webhook subscriptions. Emit one durable delivery for every persisted `tenant_surfaces.cert_state` transition on a surface explicitly linked to that tenant, inserting the delivery in the same database transaction. Include tenant identity, the stable external reference, surface and app identity, certificate state, recorded expiry, and transition time. Never include certificate/private-key material or raw provider error text.
- **Why:** DNS verification is only the first asynchronous step in bringing a customer hostname online. A platform needs a reliable signal that issuance is pending, succeeded, or failed so it can guide its customer without polling. The existing activation snapshot remains the source for aggregate readiness and current diagnostic details.
- **Consequences:** The event describes certificate lifecycle only; it does not assert that a tenant or surface is active or that routes are ready. Events are emitted only for explicitly linked surfaces, are durable and retryable, and are delivered at-least-once. No historical transitions are backfilled. Existing subscriptions that omit `event_filter` continue to receive only `platform_tenant.statement.finalized`; filters remain immutable after creation. Raw issuer errors remain available through the authorized activation snapshot rather than the event stream.
- **Rejected alternatives:** Include provider error text, which can reveal provider/internal details and changes without a state transition; call the event “surface ready,” which would collapse tenant status, all hostnames, certificate validity, and route policy into one trigger; or emit an app-scoped event, which cannot safely identify the platform customer when an app serves multiple tenants.
