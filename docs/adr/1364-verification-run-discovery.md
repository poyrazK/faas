# ADR-1364: Verification run discovery

- **Status:** Accepted
- **Date:** 2026-10-15
- **Context:** Receipt recovery requires a UUID. Lost CI output and capacity troubleshooting need read-only discovery without loading protected historical inventories or creating replacement work.
- **Decision:** Add app and project/environment GET collection endpoints, CLI `verification-runs list` and typed Go, Node and Python methods. Return compact retained summaries: identity, app/deployment/scope or project/environment, optional graph root linkage, stored state and original creation/expiry. Omit inventories, manifests, plans, policy, digests, commands, credentials and resource output. Existing read gates load the selected app/project/environment before querying the account-scoped store.
- **Pagination:** Default 20, maximum 100 results. Order by immutable creation timestamp and UUID descending; fetch one extra row to prove another page. An opaque bounded cursor binds account, owner, environment and filters, freezes an observation time and carries the last returned key. Newer creations are excluded by the observation-time cutoff. Concurrent state changes and retention pruning do not form a database snapshot; stable keyset traversal prevents repeated keys, not missing records removed or changed by another operation. Reuse filters when following `next_cursor`; page size may change.
- **Status:** Stored pending/passed/cancelled state is exposed without requalifying evidence. Noncancelled receipts expired at the cursor's observation time appear expired. Cancellation remains cancelled after expiry. A listed passed receipt is not evidence that current release checks pass; status, diagnostics, resume and traffic writes independently enforce their current checks. No list read observes underlying tasks or queue invocations.
- **Filters:** App lists support exact canonical deployment UUID, deployment scope, state and explicit `include_members`; standalone receipts are the default. Project/environment lists contain roots only and support state and any matching reviewed deployment in the graph. Graph-only calls reject app-only scope/member filters. Member entries carry `graph_run_id`, so discovery never presents them as standalone roots.
- **Storage:** SQLC queries project only summary columns and apply tenant/selector/expiry/keyset filters before a bounded limit. Composite owner/creation/UUID indexes support traversal. MemStore mirrors ordering, filters and cursor semantics. Retention and pruning behavior remain unchanged; this is retained discovery, not a permanent audit history.
- **Validation:** Tied timestamps and pagination across new inserts; account/environment/filter isolation, invalid cursors and options; root/member distinction and expiry; real PostgreSQL query contracts and index migration; HTTP read gates and no-store responses; CLI and all SDK wire contracts; generated OpenAPI/SDK parity and lint.
