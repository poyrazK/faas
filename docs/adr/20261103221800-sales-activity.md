# ADR: Staff activity history and lead attention

Status: Accepted 2026-11-04

## Context

Sales leads have current notes, ownership and follow-up tasks. Reps and managers
need a chronological record of conversations and an actionable view of leads
with no recent recorded contact or overdue follow-ups.

## Decision

Apid owns `sales_activities`, outside application clones. Staff append calls,
emails, demos and internal notes with an occurrence time, summary, outcome and
next step. Preserve the original actor, recording time and optional follow-up
snapshot. Entries are kept as recorded; corrections use another note. Deleting
a lead deletes its activities. Deleting a follow-up task preserves the entry
and its original task title/date. Actor deletion retains the entry with an
unavailable author. These are staff-entered records, not verified delivery facts.

Read and write permissions derive from the current lead owner. Managers have
team access; reassignment moves history and tasks together while preserving
original authorship. Existing session-only, verified-email, MFA and origin
requirements protect all endpoints. No public or customer-referral activity API
is added. Audit events contain IDs and activity kind, not conversation text.

A client-generated UUID identifies a save operation. Lock the scoped lead before
checking retries, optimistic lead version, creating an optional task and adding
the activity. An identical retry by the same actor returns its original result;
a changed payload or stale new write conflicts. Activity plus follow-up commit
atomically. Text is bounded, timestamps cannot be in the future or before 2000,
and stored times use PostgreSQL microsecond precision. The UI keeps an uncertain
save unchanged for retry. History uses occurrence time plus UUID pagination;
cursors bind actor, manager scope and lead. Read snapshots are consistent.

Compute attention at read time. An open lead (new/contacted/qualified/demo) is
stalled when its latest recorded call/email/demo, or creation when none exists,
is at least `FAAS_SALES_STALE_DAYS` old. Default 14; allowed range 1–365. Notes,
lead edits and task updates do not reset contact age. Backdated entries use
their occurrence time. Closed stages are excluded from stalled counts; overdue
open tasks surface for every stage. Today is not overdue. The browser supplies
its local calendar date, matching the task inbox; API callers default to UTC.

Attention lists are scoped and paginated with owner/kind/day/config-bound
cursors. Summary counts cover the selected owner scope across both reasons;
the selected reason filters rows. Active portal views refresh attention every
minute. Refreshing after local midnight starts a new page. No new daemon,
external message, browser notification, payment or referral-credit mutation is
introduced. An activity does not implicitly change a lead's stage.

## Consequences

Apply the additive migration before apid. The existing default-off sales flag
covers these private features. Reps open history from a lead or attention row;
recording an entry can create a follow-up in the current owner's task inbox.
Managers can filter attention by salesperson, including the all-team view for
leads whose previous owners are no longer configured. The current CRM editor
remains the place to change stages, ownership or delete a lead. Customer-facing
qualification forms, templates and outbound communications remain separate work.
