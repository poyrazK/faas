# ADR-522 · Deployment-pinned outbound binding verification

- **Status:** accepted
- **Date:** 2026-10-02
- **Decision:** Add explicit GET/HEAD probe policies to customer-owned outbound integrations. `bindings verify --outbound INTEGRATION_ID` and `--all` execute the configured request from the exact selected deployment's task guest through ordinary managed outbound admission. Configuring or removing a probe sends no provider requests.
- **Policy:** Require a canonical path without query/fragment, within the integration route ceiling, and a single expected 2xx response status. The owner declares the endpoint safe. The app binding's narrower route policy, workload identity, credential injection, budgets, throttling, circuit breaker, provider DNS/public-address checks, TLS and redirects retain their existing gateway behavior. The guest uses normal TLS verification, no cookie jar or environment proxy, a ten-second request budget and no response cache. Provider responses are closed without exporting bodies or headers.
- **Gateway:** `apid.toml` contains the operator-trusted `outbound_probe_gateway_url`, an HTTPS origin reachable by task guests and routed to outboundd. The guest uses its existing fixed loopback identity endpoint and requests audience `gregale:outbound:<integration-id>`. Customer task requests supply only the reserved command and integration ID; apid supplies immutable routing metadata in the task and private verification pin. A caller-supplied probe spec is rejected. No VM lifecycle or new cross-daemon RPC is introduced.
- **Evidence:** Reuse ADR-524/528 durable newest-admission evidence with separate deployment and scope selection. Pin a private digest of integration and binding metadata, plan, explicit probe policy, gateway endpoint, sealed credential digest and credential-update revision, plus the app runtime configuration stamp. Credential writes invalidate evidence even before a runtime stamp, including replacement with the same sealed bytes. The public inventory exposes probe policy and sanitized configuration/identity/gateway/response stages, never credential fingerprints, identity tokens, provider errors or task output.
- **Promotion:** Configured outbound probes participate in ADR-527/529 checks with the normal age and runtime policy. Missing, failed or stale supported evidence remains a blocker under `--allow-unsupported`. Extend the promotion fence to probe policies, credential-update revisions and outbound admission-policy fields. Existing traffic and task locks retain their ordering.
- **Coverage:** Queue bindings, outbound integrations without an explicit probe, installations without the configured gateway, and operator-environment credentials retain unsupported coverage. The first implementation supports customer-sealed credentials because their rotation is durably observable. A successful configured endpoint does not establish every provider route, application readiness or subsequent availability.
- **Persistence and rollback:** Add a separate probe-policy table, sqlc queries and a new reserved verification command. Rollback removes policies and clears only outbound pins to restore the prior task constraint; integrations, credentials, bindings, task rows and reports remain. Policies must be reconfigured after reinstallation.
- **Validation:** Test real gateway identity/route/credential enforcement and response-cache bypass with an HTTPS provider fixture; rejected credentials, denied routes, redirects, TLS failure and cancellation cannot pass. Test MemStore/PostgreSQL catalog changes, exact-candidate evidence, rotation before stamps, supported-probe waiver behavior, immutable task specs, CLI/SDK wire contracts and migration rollback.
