# ADR-1377: Python storage explicit TLS trust

- **Status:** Accepted
- **Date:** 2026-10-15
- **Context:** The Python storage starter passes `verify=True`, bypassing aiobotocore's `AWS_CA_BUNDLE` resolution. Public CA verification works, but an explicitly configured private CA bundle has no effect. Existing signed storage acceptance uses HTTP and cannot catch certificate or hostname failures.
- **Decision:** Capture the application environment once and pass its explicit `AWS_CA_BUNDLE` path to every new S3 client. With no setting, retain `verify=True` and bundled public CA trust. Reject empty, non-string and control-character settings inside the coordinated factory; never pass false verification settings or allow ambient AWS profile trust to override the supplied environment. Let the real TLS driver verify the file, certificate chain, validity and hostname before adoption. Trust failures follow existing failed-ACK/readiness and restore behavior, with sanitized errors. The path is process configuration; each new transport rereads its contents. No canonical SDK, API, schema, quota, dependency pin, guest or hypervisor changes.
- **Acceptance:** Reuse the complete signed transfer, rotation, no-replay, cancellation, restore and real handler-process journey over HTTPS with ephemeral OpenSSL-generated CA/server certificates. Keep guest-like ACKs on a separate owned HTTP loopback listener. Reject unrelated CAs, wrong hostnames, expired certificates, missing/empty/malformed bundle files, directories and invalid setting types without sending object credentials/bytes or applied ACKs. Verify readiness stays closed, an actual failed-startup process excludes private diagnostics, and corrected-bundle reload plus same-revision restore use fresh transports while preserving the sticky failed-restore gate.
- **Packaging:** Run HTTPS acceptance from the exact materialized CLI artifact in existing CI lanes, with mandatory OpenSSL availability and packaged fixture/test checks. OpenSSL is a test prerequisite, not an application dependency. Portable HTTPS evidence does not qualify live providers or native VM snapshots.
