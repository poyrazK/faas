# ADR 1461: App-scoped issue teams and explicit CODEOWNERS import

Status: Accepted

## Decision

Add real issue teams with a name, stable key, immutable UUID, and complete member roster. Scope teams to an app: Gregale has organization membership but no general organization team/access model. Team membership does not grant app permissions. Each member must already be the app owner or an active organization member when the roster is saved. Up to 20 teams per app and 50 distinct members per team; stable key and name bounds reuse shared view bounds (48 lowercase ASCII key bytes, 64 UTF-8 name bytes).

An issue has one assignment target: an eligible account, an app-scoped team, or neither. Teams are independent of any designated triage account. A team inbox is the live issue list filtered by its UUID; dashboard and CLI inbox links show open groups by default. Saved views can persist a team filter, mutually exclusive with the account/unassigned filter. Cursors bind the team along with existing filters. Team CRUD uses the existing app authorization, Issues entitlement, deployment-write permission and session MFA; dashboard writes also verify the existing Issues CSRF token.

Validate a team's app and at least one currently eligible member for new automatic or manual assignments. Retain first-matching-rule precedence: if all members lose eligibility, leave a new group unassigned instead of silently choosing a later route. Removing organization membership does not erase existing assignment history. Recurrence, regression, lifecycle changes, merge, split and occurrence split rules preserve the established assignment semantics. Assignment activity/webhooks contain the team UUID. Composite foreign keys prevent cross-app team references; the database rejects simultaneous account/team targets. Team changes and routing use the app lock. Refuse team deletion while issues or routing rules reference it. Teams and rosters are operational collaboration metadata, excluded from workload cloning. The migration refuses rollback while teams or saved team filters are present, preventing an older reader from silently widening an inbox.

Import CODEOWNERS locally through `issues codeowners preview|apply`, with explicit JSON owner bindings and a deployed source root. Bind handles/emails to account UUIDs or team UUIDs; never fetch accounts, repository content, or provider identities implicitly. Reverse rule order to preserve last-matching-line precedence. Require all listed owners to be bound and choose the first owner on a multi-owner line, because Gregale assigns one target. Support root defaults (`*`, `/`, `/**`) and literal root-anchored paths only. Unsupported globs, unanchored basenames, ownerless entries, traversal, URLs and malformed bindings fail the entire import. Bounds: 256 KiB input, 4096 lines, 256 bindings, and the existing 50-rule policy cap. `apply` requires `--replace` and replaces the entire prospective policy through the existing authenticated API; preview performs no API requests.

## Consequences

Teams have actual members and shared inboxes without relying on a lead account. Teams are app-scoped rather than reusable organization-wide; a future organization team model will require an explicit migration. CODEOWNERS support is a documented literal-path subset, not GitHub glob parity, automatic synchronization, or multi-owner assignment. Existing saved team views become empty if their unreferenced team is explicitly deleted; recreating the key produces a new identity, so old views do not silently retarget. Provider integrations and crash-free sessions remain separate work.
