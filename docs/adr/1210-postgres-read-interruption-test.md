# ADR-1210 · One-shot connection interruption inside a PostgreSQL TLS row

- **Status:** accepted
- **Date:** 2026-10-12
- **Decision:** Extend the opt-in loopback TLS fixture with `armReadCut({afterBytes})`. Select the next DataRow whose bounded frame exceeds the configured integer 1–1048575 byte offset. Forward that row prefix through the existing response pacing, confirm its local flush callback, then destroy both connection ends. Consume the arm atomically on selection; concurrent streams and subsequent connections continue normally. Short rows and non-DataRow frames do not consume the arm. Clear releases a selected row's remainder in order; disconnect/shutdown cancellation is distinct from a fired cut.
- **Why:** Slow transfers and proxy-wide shutdown do not prove that one application rejects an incomplete row after a targeted mid-response disconnect while other connections remain usable.
- **Consequences:** Bounded evidence reports offset, selected frame size, locally flushed prefix bytes, monotonic duration and armed/forwarding/cut/clear/cancel outcomes without SQL, row data, credentials or identities. A proxy accepts at most 100 cut records. The parser first receives the complete bounded upstream frame, so this tests a partial client response rather than upstream execution. Portable plaintext/TLS tests independently verify exact prefixes, one-shot and concurrent isolation, threshold negative controls and clearing/canceling during pacing. Real TLS PostgreSQL tests cut a 64 KiB row, require query rejection with zero row callbacks, retire the broken connection and independently verify old-backend removal. A fresh backend must return the full read with verified encryption; shutdown leaves no sessions, timers, buffers or active cuts. Native/deployed qualification remains a separate release gate.
- **Rejected alternatives:** Cutting immediately after socket write without a flush callback could discard all prefix bytes. A local flush alone is not proof of receiver delivery, so receiving tests must verify the prefix. Summing bytes from concurrent connections could fire a cut on the wrong stream. Returning a parsed partial row or reusing a broken response stream would hide the read failure. Promise of a specific TCP RST or graceful TLS shutdown would exceed the portable socket-destroy contract.
