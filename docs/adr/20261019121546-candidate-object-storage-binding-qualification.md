# ADR-20261019121546: Managed object storage bindings in candidate binding qualification

- **Status:** accepted
- **Date:** 2026-10-19
- **Related:** ADR-20261019072523, ADR-1646, ADR-526, ADR-284
- **Problem:** ADR-1646 blocks enforced activation of a managed GitOps graph when a member has an active managed object storage binding, and rejects any enforced policy with `object_storage_requirements`. Applications with buckets therefore cannot use binding enforcement.
- **Decision:** Extend the control-plane credential receipts of ADR-20261019072523 to managed object storage. Before activation, apid opens the six sealed app secrets an enforced candidate receives for each active managed S3 credential (`_ENDPOINT`, `_REGION`, `_BUCKET`, `_ACCESS_KEY_ID`, `_SECRET_ACCESS_KEY`, `_ADDRESSING_STYLE`), requires each envelope fingerprint to match, and runs the existing `bindingprobe` canary against the public endpoint those secrets name. Candidates keep the `QualificationOnly` network policy and never reach the bucket.
- **Probe mode:** The policy requirement for the binding's prefix selects the probe: `read` lists one key; `write` uploads and cleans up; `read_write` also downloads byte for byte. Without a requirement, a write-only credential uses the write probe and every other credential the read probe. Write probes use the ordinary verification's disposable object and cleanup.
- **Receipt:** One immutable receipt per request attempt and credential names the prefix, permission, probe mode and the six secrets' delivery versions. Insertion requires an enforced binding context, a live qualification lease, an active managed credential with no pending rotation stage, matching permission and prefix, and the exact current deliveries. Downgrade refuses to discard receipts.
- **Activation:** For each active managed credential of a candidate's app and scope, a receipt must exist whose deliveries are contained in both the captured and restored runtime inputs and equal the current deliveries; its mode must cover the policy requirement, and the credential's permission must too. Every policy requirement must name an active binding. The receipt's age bounds authority by the policy's maximum verification age. `environment_binding_catalog_supported` no longer excludes object storage. Rotation changes deliveries and runtime configuration, so it invalidates both the receipt and the candidate's qualification.
- **Outbound integrations stay blocked:** Outbound evidence is a platform-signed workload identity for a running instance, admitted by the outbound gateway, which then calls the third-party provider. A held candidate has no admissible identity and its network cannot reach the gateway. Qualifying it needs a separate decision: mint candidate identities and admit held deployments at the gateway, or open candidate egress to the outbound gateway. Both change security boundaries and need their own ADR.
- **Limits:** Credential and bucket-access evidence, not proof that candidate code uses the bucket. Native KVM acceptance and qualification dispatch remain pending.
- **Validation:** Portable memory and PostgreSQL tests cover read and write requirements, missing receipts, a requirement without a binding, insufficient permission, pending rotation and receipt immutability. apid tests cover secret decryption, fingerprint substitution, probe-mode selection and probe failure.
