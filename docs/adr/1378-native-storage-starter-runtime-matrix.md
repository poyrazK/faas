# ADR-1378: Native storage starter runtime matrix

- **Status:** Accepted; native execution pending
- **Date:** 2026-10-15
- **Context:** ADR-1376 implements the deployed storage journey for Node only. ADR-1377 gives Python strict explicit TLS trust and portable signed HTTPS coverage, but does not prove its driver, signal handling or recovery inside actual builder/serving guests and snapshots.
- **Decision:** Run the unchanged embedded Node and Python storage starters through the same eight native acceptance phases. Select source, public CA environment and language-family label from an explicit contract: `object-storage-node` / `NODE_EXTRA_CA_CERTS` / `node22`, and `object-storage-python` / `AWS_CA_BUNDLE` / `python312`. Each sequential journey owns a separate disposable catalog schema, application, bucket, TLS gateway and daemon harness. Add only the public CA under the shipped runtime COPY; keep application files, requirements, readiness and restore budgets unchanged. No production API, SDK, schema, quota or VM behavior changes.
- **Provenance correction:** These Dockerfile starters run as full OCI apps, with interpreters in drive1 and the shared minimal base in drive0. They do not publish function-runtime releases; ADR-1376's Node runtime-release lookup could never qualify this path. Instead, require a successful source build with pinned OCI digest, compare the owned exact archive hash against deployment and builder provenance, and hash the actual deployed app layer, retained source archive and shared minimal base. Runtime labels describe the shipped Dockerfile language family, not an independently measured interpreter version. Keep source evidence alive through the whole journey and rehash every execution artifact before cleanup.
- **Evidence:** Upgrade the suite and report to version 2. Require both complete ordered journeys, every phase and parent/package pass, and a separate identity emitted after each starter's registered cleanup. Bind each identity to its template, runtime label and source/app-layer hashes; reject reused or renamed Node identity/artifacts for Python, partial/old Node-only results, mixed revisions and changed shared executable/guest/kernel/builder/minimal-base/Firecracker artifacts. Preserve existing native-host, clean-source, no-overwrite and before/after leak requirements. Nested diagnostics cannot qualify. Allow 60 minutes for both journeys.
- **Validation:** Portable source tests compare every packaged file for both starters and enforce public-certificate-only fixture additions. Manifest and verdict regressions reject missing/foreign application artifacts, mismatched/failed build provenance, changed source archives, incomplete or reordered journeys, premature/duplicate identities, reused starter bytes and mixed execution bundles. Reassemble Go test2json's fragmented cleanup identity lines with a 16 KiB bound; reject truncated, interrupted or oversized output. CI runs these checks and compiles the combined binding-native tags. Supported native KVM execution and host leak qualification remain required and cannot be claimed from portable checks; live-provider durability and public-network behavior remain separate.
