# ADR-448: Saved app route requirements and snapshot checks

- Status: Accepted
- Date: 2026-10-02
- Related: ADR-436 (requirements), ADR-445 (complete captured coverage),
  ADR-446 (group planning), ADR-438 (transactional apply)

## Context

File-based checks require each caller to supply intent and can miss new
operations when using concrete version 1 requirements. Customers need a shared
current route policy expectation and a reproducible deployment-specific CI
check. Concurrent updates must not silently replace another customer's review.

## Decision

Add one current `saved_route_requirements` row per app, owned by apid and accessed
through account/app ownership checks. Store canonical version 2 intent, its
SHA-256, a monotonically increasing revision and update time. Version 2 assigns
every captured operation. Keep version 1 for existing file-based workflows.
Require an explicit expected revision on PUT, including zero for the first save.
Serialize writes with the existing app policy lock. Stale revisions return 409;
identical normalized intent at the current revision is a no-op. Bound revisions
to the safe JSON integer range and preserve existing byte/count limits.

Normalize and validate semantics at the apid boundary using the existing parser.
Share dependency-free canonicalization in pkg/api so state can independently
enforce container bounds, redact public rationale, hash and isolate persisted
intent without importing the evaluator. Stored reads verify identity, revision,
fingerprint and the fixed public marker; evaluation performs full semantic
validation again. All SQL is generated by sqlc. The table is deleted with its
app/account. Original rationale remains in customer-controlled local files.

Add GET/PUT `/v1/apps/{slug}/route-requirements` and POST
`/v1/apps/{slug}/route-requirements/check`. GET/check use app read scope; PUT
uses deploy-write scope. Apply the existing MFA protection. Audit saved intent
with app identity, revision and fingerprint only. Require an explicit canonical
app-owned deployment UUID on checks and allow a positive expected revision pin.

Read saved intent, current account/app/rules and selected capture in one memory
mutex or PostgreSQL repeatable-read read-only transaction. Reuse captured
contract entitlement, inventory parsing and the existing requirements evaluator.
Return version 1 check envelopes containing the version 2 coverage report, app
and deployment identity, intent revision/hash and configuration hash. Findings
are 200 responses, including violations and unavailable/uncertain inventory.
Missing saved intent or a foreign deployment is 404; stale pinned intent is 409.

Expose `routes requirements set|get` and `routes check`. Validate explicit flags
before authentication and bind returned checks to the requested app, deployment
and optional revision before exporting or gating. `--fail-on-requirements` exits
1 for violated or unknown reports after output/export. Export with the existing
atomic owner-only new-file writer. GET exports plain normalized requirements
that the existing file-based planner accepts; apply still uses a reviewed plan
and its existing transactional verification and receipt.

## Consequences

Customers can share current intent and detect policy drift or unassigned new
endpoints in CI. The check concerns configured policy on the platform hostname,
not historical policy for the selected deployment, live enforcement or business
authorization. The database retains only current intent; Git owns older
versions. There is no automatic capture-triggered check, persisted check history,
deployment gate, gateway change or application request in this slice.

## Validation

Exercise memory and PostgreSQL ownership, first save, unchanged intent, concurrent
revision conflicts, isolated returned values and checks after policy/capture
changes. Cover complete/incomplete inventory, configured auth/budget drift,
unknown selection and provenance. API tests cover strict inputs, read/write
scopes, MFA and foreign captures. CLI tests cover rationale privacy, planner
export, pinned response identity, CI gate ordering and existing/symlink targets.
Regenerate SQL, OpenAPI SDKs and CLI reference; run spec parity and scoped lint.
