# ADR-1371: Async Python PostgreSQL bindings

- **Status:** Accepted
- **Date:** 2026-10-15
- **Context:** Python HTTP SDKs support asyncio, but the synchronous secret coordinator and pool helper run application callbacks/retirement on threads and reject async pool factories. Loop-owned drivers such as psycopg's `AsyncConnectionPool` need native async adoption and retirement.
- **Decision:** Add separate `async_secret_reload_runtime` and `async_postgres_pool_runtime` modules, keeping existing synchronous APIs compatible and SDK core free of database/framework dependencies. Share strict guest settings validation and PostgreSQL URI parsing with synchronous helpers. Preserve both handwritten modules during SDK regeneration.
- **Protocol:** One coordinator owns SIGHUP on the main-thread event loop. Await startup before admission; use the modern atomic snapshot/readiness/ACK/generation contract without stale environment fallback. Serialize consumers, validate every adoption before an applied ACK, retry transient missing-file lookups and bounded ACK transport/503 responses, and reread on 409. Reject malformed projections and async invalidation callbacks. Failed consumers invalidate every registered user.
- **Cancellation:** Startup and optional manual budgets bound the entire attempt, including queueing and ACK. Queued cancellation does not invalidate an earlier successful attempt. Admitted cancellation synchronously fences consumers, preserves native `CancelledError`, and prevents late publication/ACK initiation. Owned tasks remain tracked for draining, including callbacks that suppress cancellation. Cancellation cannot retract an ACK already sent or committed database work. A failed manual adoption can recover with another reload; startup failure/shutdown is terminal for that coordinator.
- **Pool ownership:** Async factory, validator and retire hooks execute on the owning loop. Immediate synchronous acquire/release/invalidate gates avoid cancellation gaps; leases support `async with` and pin pools through complete transaction/connection return. Factories exclusively own partial allocations until returning a fresh pool. Reject tracked aliases before validation without closing existing borrowers. Retire rejected/old candidates once after their final lease. Cleanup failures remain sticky and sanitized. No SQL replay or credential-validity extension.
- **Shutdown:** Stop admission, synchronously stop the coordinator, await its owned tasks, then await admitted pool operations and retired leases/cleanup before closing the loop. Wait timeout/cancellation does not forcibly close a leased pool or cancel its cleanup. Hooks must bound I/O. No guest, hypervisor, server API, quota or VM lifecycle changes.
- **Application:** Add a single-worker FastAPI lifespan example using psycopg `AsyncConnectionPool`. Require explicit verified TLS, bound connection/SQL/request/shutdown waits, validate before serving, sanitize application errors, and retain each lease through driver context exit. The existing built-in Node starters stay independently usable.
- **Validation:** Async contract tests exercise loop ownership, validation gates, lease copying/draining, factory/validator cancellation suppression, queued cancellation, SIGHUP, ACK ordering/retries/conflicts, malformed startup, observer errors and sticky retirement failure. Opt-in real TLS/SCRAM PostgreSQL tests load the exact ASGI example, rotate credentials with an open write, reject stale credentials, revoke new work, retain liveness, prove one committed row, cancel a blocked validator without an applied ACK, recover, cancel a transaction and drain every pool. Portable application evidence does not replace native microVM restore acceptance.
