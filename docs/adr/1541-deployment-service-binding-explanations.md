# ADR-1541: Deployment service binding explanations

- **Date:** 2026-10-17
- **Status:** accepted
- **Context:** App-level service explanations do not resolve the frozen workload policy and active reviewed routes used by managed environment deployments. App settings alone cannot explain why an exact deployed caller is denied.
- **Decision:** Add a read-only app-scoped service explanation API and `gregale bindings service explain CALLER SERVICE --deployment ID`. Infer the environment from the app-owned caller deployment; optional `--scope` asserts that environment. Keep the existing app-only command compatible.
- **Authority:** Share the existing app authorizer and canonical alias authorizer with the gateway. Use the existing managed environment binding and project release resolvers. Managed binding misses never fall back to global app names. Frozen method/path and transport settings replace app-level values only after the gateway's app authorization succeeds. Ordinary routes may remain unpinned and report no target deployment; retained project releases retain their existing routing semantics.
- **Observation contract:** Report deployment/release identities, policy source, effective transport and stable sanitized rule reasons. Policy denials use `denied`; missing permissions, unsupported preview/qualification contexts and failed reads use `indeterminate`. Missing or foreign caller deployments return HTTP 404. The deployment selector is not live caller authentication. Separate reads are not an atomic snapshot, connectivity probe, application acknowledgement or release approval. No guest calls, tasks, writes or provider calls occur.
- **Compatibility:** The CLI must not fall back to app-only evaluation when a deployment explanation is unavailable or malformed. Preserve exit codes 0 allowed, 1 denied and 2 indeterminate/error. Strip query values from public reports and CLI requests. Publish typed Go, Node and Python contracts from the public OpenAPI surface.
- **Validation:** Cover effective frozen policy, missing and stale release membership, managed misses without fallback, scope assertions, same-account boundaries, failed-read sanitization, selector validation, CLI response identity validation and the gateway's existing authorization regressions.
