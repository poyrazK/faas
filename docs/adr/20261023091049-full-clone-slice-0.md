# ADR-20261023091049: Full environment clones, slice 0 — a measurable gap and a dormant switch

Date: 2026-10-23
Status: Accepted
Amends: ADR-590 (complete project-environment clones)
Related: ADR-1700 (platform flags and runtime configuration), ADR-233 (environment route contracts)

## Context

ADR-590's full clone (`gregale env create staging --from production --full`)
is not admitted: apid answers every full request with
`environment_full_clone_unavailable`, and no production code creates a clone
operation. Three things made that state costly and opaque:

- **The gap could not shrink.** The clone schema registry classified every
  table, but every configuration and customer-data table reported a permanent
  strategy blocker with nothing able to clear it. The ADR-590 bar for a
  configuration table is an environment-scoped capture, materialization, diff,
  qualification, promotion and rollback; the registry recorded none of that,
  and each new feature table added another unmeasured blocker.
- **Dormant machinery ran on the live fleet.** schedd recorded clone wake and
  migration ownership on every wake and migration, gatewayd-internal read the
  clone operation for every stage-URL request, and apid's in-process clone
  coordinator polled an always-empty queue every five seconds. None of these
  can find a full-clone operation today.
- **The CLI advertised what apid refuses.** `env create --full --wait` was the
  reference example and `env clone-status` was documented, though both can only
  fail.

## Decision

1. **Registry capabilities.** Every `configuration` and `customer_data` entry in
   `pkg/state/project_environment_clone_schema_registry.json` declares
   `capabilities` explicitly, even as `[]`; other kinds declare none, and the
   registry fails to load otherwise. A configuration table needs `capture`,
   `materialize`, `diff`, `qualify`, `promote` and `rollback`; retained customer
   data needs `capture` and `materialize` (stage data is never promoted back).
   A table reports its strategy blocker until it has all of them.
   `ProjectEnvironmentCloneCapabilityProgress` counts complete tables and each
   capability per kind. Capabilities are registry facts only: they never enter
   an observed table or the schema hash, so committed operations keep their
   frozen catalogue identity. The baseline declares no capabilities: a
   capability is added only with production code evidence for that table.
2. **One dormant switch.** The runtime setting `full_environment_clones_enabled`
   (default off, hot) gates the machinery only full clones use:
   - schedd's clone wake-dispatch, migration-adoption and migration-resume
     recorders, which only ever record for `environment-clone:` deployments;
   - gatewayd-internal's clone readiness read for stage URLs; legacy partial
     clones create no operation, so the read always missed;
   - apid's in-process clone coordinator, which waits until the switch is on and
     then keeps running, so turning it off never strands an operation. The
     dedicated `apid --clone-worker` stays a separate opt-in.
   schedd and gatewayd-internal start with the switch on and apply the durable
   value at their first reconcile, so a failed reconcile keeps the fences rather
   than dropping them. Before admitting full clones, turn the switch on and wait
   for every daemon's ADR-1700 apply receipt.
3. **The configuration write fence is switched off.** Migration
   `20261023115254527` adds `set_full_clone_configuration_fences(enabled)` and
   disables `clone_configuration_write_fence` on the 33 configuration tables it
   guards. It switches the triggers in table-name order, so concurrent callers
   lock in one order. `object_version_protection` keeps its trigger, which also
   keeps original Object Lock protection evidence immutable. Guard rows keep
   being created by their own trigger, so re-enabling needs no backfill.
   Opening admission calls `set_full_clone_configuration_fences(true)` first:
   `ENABLE TRIGGER` takes SHARE ROW EXCLUSIVE on each table and so waits for
   in-flight writers, after which every write fires the fence and a capture's
   clock update drains the rest. Tests that exercise the fence enable it in
   their fixtures.
4. **CLI dark launch.** `env create --full/--wait/--timeout` and
   `env clone-status` leave every CLI surface (help, completions, man pages, the
   generated reference, dispatch and flag parsing) unless
   `FAAS_FULL_ENVIRONMENT_CLONES_ENABLED` is set in the shell.

Not gated, because customer features depend on them: object writer custody (a
write made without tracking can never be proven drained for a later capture,
and node settlement joins upload-bound rows), the `production_invocation_work`
view and invocation claim locks (stage queue isolation), and
`instance_layer_artifact_guard` (layer-artifact garbage collection).

## Consequences

- The clone gap is a number that moves: per-kind complete counts and
  per-capability counts, and a new configuration table is a deliberate entry
  rather than a silent default.
- Ordinary wakes, migrations and stage-URL requests stop paying for full-clone
  bookkeeping. The wake recorder's incidental check that the instance is still
  waking on that node also stops while the switch is off; it was never part of
  ordinary wake admission.
- Writes to apps, deployments, environment values, queue bindings and the other
  fenced tables no longer pay two `to_jsonb` calls and shared locks on the
  fleet-wide clone clock and the project guard row. A project whose guard row is
  missing no longer fails those writes while the fence is off.
- The fence's state is part of the schema (`schema.sql` records the disabled
  triggers), so admission cannot open by accident: it needs a migration that
  re-enables them, ahead of the admission code.

## Rejected alternatives

- **An early return in the fence trigger on a config row or session GUC.** A
  writer whose snapshot predates the switch would skip the fence while a capture
  starts; closing that gap needs a lock as costly as the current one, and the
  fence deliberately has no caller-settable bypass.
- **Marking capabilities from partial support.** Counting a table as covered
  because the legacy clone copies it would hide the promotion and rollback work
  the full clone still needs.
